## MISP의 Event와 보안 이벤트는 다른 말이다

MISP Event는 관련 정보와 맥락을 묶는 공유 단위입니다. 로그인 한 건을 기록한 보안 이벤트, TheHive의 Case, MISP Event는 목적과 구조가 다릅니다. 같은 사례를 다루더라도 기록을 그대로 복사하기보다 각 시스템의 역할에 맞춰 연결해야 합니다.

교육용 Event에는 사례 설명, 관측 시각, 출처, 값과 관련 판단을 넣습니다. `192.0.2.80`이 가상 값이라는 점과 자동 차단 대상이 아니라는 제한도 함께 남깁니다. Event 제목만 “악성 IP”라고 쓰면 소비자가 맥락을 오해할 수 있습니다.

## 객체별 역할

| 구성 | 역할 | 활용할 때 주의할 점 |
| --- | --- | --- |
| Attribute | 유형이 있는 개별 값과 설명 | 값만 보고 악성 의미를 가정하지 않음 |
| Object | 관련 속성을 구조로 묶음 | 역할 관계가 중요한 정보를 낱개로 잃지 않음 |
| Taxonomy | 일관된 의미의 구조화된 태그 | 태그 이름·의미·버전을 확인 |
| Galaxy | 관련 군집·지식의 맥락 | 유명 그룹 태그가 귀속 증거가 되지는 않음 |
| Sighting | 관측·거짓양성·만료 등의 피드백 | 어떤 자료와 판정에 따른 피드백인지 확인 |

파일 정보는 해시 하나보다 파일명·크기·경로·해시의 관계가 필요할 수 있습니다. 네트워크 정보도 도메인·IP·인증서·역할 관계가 중요할 수 있습니다. 사용할 Object 템플릿과 필수 속성은 현재 문서와 제품에서 확인합니다.

## 상관은 관계를 찾고 인과는 조사한다

두 Event에 같은 도메인이 있으면 관련 가능성을 검토할 수 있습니다. 그러나 공유 호스팅, 공개 서비스, 오래된 지표, 잘못된 유형도 상관을 만들 수 있습니다. 동일 값이 나타났다는 것만으로 같은 공격자·같은 캠페인을 확정하지 않습니다.

공통 사례에서는 같은 세션 ID와 계정, 출발 IP, 시간 관계가 D05·D07을 연결합니다. 외부 피드에서 같은 IP 하나가 나타났다면 그 출처·관측 기간·역할을 추가 확인해야 합니다. 문서용 IP의 외부 상관은 실제 위협 근거로 사용하지 않습니다.

## 배포 범위와 탐지 사용은 별개다

배포·Sharing Group은 누가 정보에 접근하거나 공유할 수 있는지 정하는 데 사용됩니다. `to_ids`는 속성을 탐지 활용에 보낼지 결정하는 데 중요한 설정입니다. 넓게 공유한다고 탐지 적합성이 높아지는 것도 아니고, 탐지에 사용한다고 넓게 배포해야 하는 것도 아닙니다.

내부 자산 IP, 사용자 정보, 사건 식별자처럼 조사 맥락에는 유용하지만 외부 탐지 지표로 부적합한 값이 있습니다. 경고 목록과 내보내기 설정도 결과에 영향을 줄 수 있으므로 실제 소비 시스템에서 어떤 값이 전달되는지 검토합니다. 이 실습의 가상 값은 탐지 자동화와 외부 동기화에 쓰지 않습니다.

## TLP와 제품 권한의 관계

현재 FIRST TLP는 정보 공유 경계를 표현하는 데 사용합니다. 태그를 붙였다고 제품 접근 권한과 동기화 경로가 자동으로 모두 맞춰졌다고 보지 않습니다. 조직의 정책, Event·Attribute의 배포 범위, Sharing Group, 동기화와 내보내기를 함께 확인합니다.

실제 사건을 공유할 때는 공개할 필요가 있는 값과 민감한 맥락을 구별합니다. 출처가 정한 공유 조건도 확인해야 합니다. 가상 사례에서는 내부 교육 범위로 유지하고, 공개 연구 결과와 구별되도록 제목·설명에 표시합니다.

## 작성부터 공유까지의 검토 순서

초안을 만들고 값의 유형·역할·시각·출처를 채웁니다. 상관 결과를 검토한 뒤 확신·공유·탐지 사용을 설정합니다. 내부 검토 후 필요한 범위에 발행하고, 소비 결과와 피드백을 갱신합니다. 발행이 모든 상대에게 즉시 동기화됐다는 뜻은 아니므로 실제 설정과 소비 결과를 확인합니다.

학습 활동으로 워크북에 “내부 맥락”, “공유 가능한 값”, “탐지에 사용 가능한 값”을 각각 표시하세요. 세 집단이 항상 같은 목록이 아니라는 점을 설명할 수 있어야 합니다.
