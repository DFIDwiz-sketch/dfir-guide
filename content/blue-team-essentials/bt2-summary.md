## 정상 동작에서 분석으로

네트워크를 조사할 때 구조와 수집 위치를 먼저 확인합니다. 자료가 무엇을 남기는지 정한 뒤 DNS의 이름 해석, HTTP의 요청·응답, SMTP의 전달·발신 평가, DHCP·원격 접속의 자산·사용자 행동을 연결합니다.

## 주제마다 답할 기본 질문

| 주제 | 설명할 내용 | 한계 |
| --- | --- | --- |
| 구조 | 영역·경로·센서·NAT·프록시 | 관측 밖 통신 |
| 수집 | 흐름·프로토콜 로그·패킷 | 표본·손실·보존·암호화 |
| DNS | 질의자·리졸버·답·기간 | 캐시·공유 IP·현재/과거 차이 |
| HTTP | 이름·URI·메서드·응답 | 파일 수신과 실행의 차이 |
| 메일 | 전달·헤더·신뢰 경계·인증 | 인증과 콘텐츠 안전의 차이 |
| 원격 접속 | 자산·연결·계정·대상 행동 | 연결·인증·실행의 차이 |

## 가상 자료를 하나의 타임라인으로

[가상 기록 20개](network-capstone.html)를 event_ts로 정렬합니다. 파일 순서와 시간순서가 다를 수 있습니다. DNS 답과 웹 목적지를 비교하되 UID를 같은 값으로 기대하지 않습니다. 메일·로그인·규칙과 네트워크 행동은 연결 근거가 있는 범위까지만 기록합니다.

## 조사 메모의 필수 항목

대상·기간·센서·원문·해시·필드·시간대·보존 조건을 적습니다. 각 판단에 증거 ID를 붙이고 정상 설명·추가 수집·미확인 결과를 나눕니다. PCAP이 만료됐거나 TLS 본문이 없으면 그 제한을 결론에 반영합니다.

## 작은 활동 — 인계문 작성하기

확인된 사실 3개, 미확인 관계 2개, 다음 담당과 작업 2개를 적습니다. 자료 부재를 공격 부재와 같은 말로 사용하지 않습니다.

**완료 기준:** 수집 조건과 프로토콜 의미, 사실·가설·한계를 다른 분석가가 재확인할 수 있습니다. 다음 [메일 실습](bt2-mail-lab.html)에서 원본 헤더와 신원 감사를 연결합니다.
