## 웹 통신의 악용과 분석 질문

HTTP는 피싱·파일 전달·취약점 요청·C2·업로드 등에 사용될 수 있습니다. 프로토콜 자체가 악성이라는 뜻은 아닙니다. 정상 동작을 기준으로 자산·요청·응답·후속 행동을 검토합니다.

## 빠른 보강과 원문 분석

URL·도메인 평판, 기존 내부 관찰, 업무·소유자 정보는 조사 후보를 좁힙니다. 평판이 없다는 것은 새 이름·미관측일 수도 있습니다. 의심 링크를 업무 브라우저에서 열어 결과를 확인하는 대신 보존된 자료·허용된 분석 환경을 사용합니다.

외부 검사 서비스에 전체 URL을 넣으면 토큰·내부 경로 등도 전송될 수 있습니다. 조회·샌드박스 동작의 범위와 기록을 관리합니다.

## 헤더·쿠키·인코딩

| 관찰 | 검토할 것 | 단정하면 안 되는 것 |
| --- | --- | --- |
| 특이 User-Agent | 실제 프로그램·정상 대조 | 문자열만으로 특정 악성코드 |
| 쿠키의 긴 값 | 세션·추적·인코딩·관련 행동 | 모든 긴 쿠키가 C2 |
| Base64처럼 보이는 값 | 형식·해독 결과·용도 | 암호화 또는 악성으로 자동 판정 |
| 숫자 IP로 접속 | 앱·프록시·업무·Host 관계 | 직접 IP는 모두 공격 |
| 반복 GET/POST | 정상 주기·자산·내용·응답 | 주기성만으로 비콘 확정 |

Base64는 바이트를 문자열로 표현하는 인코딩이며 암호화가 아닙니다. 가상 문자열 U3R1ZHk=는 Study를 표현합니다. 해독은 읽기 작업이며 출력 내용을 명령으로 실행하지 않습니다.

## 파일 수신과 실행

파일 추출이 가능하면 완전한 수신 여부·크기·MIME·파일 ID·해시와 원본 출처를 기록합니다. 확장자와 콘텐츠가 다를 수 있고 부분 자료는 완전한 파일과 구분합니다.

HTTP 200 또는 추출 파일만으로 실제 저장·실행을 증명하지 않습니다. 호스트 파일·프로세스·브라우저·서버 실행 자료를 연결합니다. 웹 취약점 요청은 WAF와 백엔드·프로세스·변경 자료로 결과를 확인합니다.

## HTTPS에서 볼 수 있는 것

주소·크기·시각·연결 패턴과 관찰 가능한 TLS 핸드셰이크를 사용합니다. TLS 1.3에서는 인증서가 암호화되는 구간에 있고 ECH는 실제 이름을 가릴 수 있습니다. 승인된 복호화 자료가 없으면 URL·본문을 읽었다고 기록하지 않습니다.

JA3·JA3S 같은 수동 지문과 JARM 같은 능동 탐색 지문은 생성 방식이 다릅니다. 지문은 도구 버전·환경에 영향을 받고 공유될 수 있으며 단독 악성 증거가 아닙니다. Salesforce의 JA3 저장소는 2025년에 보관 상태가 됐으므로 개념 설명용 원출처와 현재 센서의 지원·유지 상태를 구분합니다.

**작은 활동:** 한 요청을 “관찰”, “가능한 정상 설명”, “추가 확인” 세 열로 정리합니다.

**완료 기준:** 파일 전달·실행·C2·유출의 결론에 각각 필요한 증거를 설명합니다.
