## 탐지 조건을 만들기 전에 목표를 적기

탐지의 목표가 계정 오용에 따른 메일 노출을 줄이는 것이라면, 필요한 행동은 로그인과 메일 설정 변경의 관계입니다. 단순히 “실패 로그인 세 번”을 선택하는 것은 다른 목표일 수 있습니다. 실패 수를 늘리거나 줄이는 것보다 무엇을 보호하고 어떤 행동을 찾는지 먼저 설명해야 합니다.

공통 사례는 실패 D03·D04 뒤 S002 성공 D05와 규칙 생성 D07이 이어집니다. 하지만 실패와 성공의 연결만으로 같은 사람이 암호를 추측했다고 확정하지 않습니다. 계정·IP·세션·인증 방식·기타 감사와 정상 맥락을 확인해야 합니다.

## 데이터 계약을 정의하기

자료 출처, 필요한 필드, 각 필드의 의미, 시각, 누락 처리와 예상 지연을 정합니다. 세션 식별자가 없다면 같은 계정·IP·기간으로 근사할 수 있지만 정확한 세션 연결보다 약합니다. 그 제한을 명시해야 합니다. 계정 표시 이름과 고유 ID가 다른 경우 어떤 키를 사용할지도 정합니다.

| 필드·조건 | 필요한 이유 | 없을 때의 처리 |
| --- | --- | --- |
| account | 사건의 계정 범위 | 탐지 평가 불가, 자료 품질 확인 |
| session_id | 같은 세션 관계 | 약한 연결만 가능, 제한 표시 |
| event_type | 로그인·설정 변경 구별 | 파서·출처 필드 확인 |
| @timestamp | 순서와 시간 창 | 시각 해석 검토 |
| received_at | 지연 평가 | 수집 지연 미측정 표시 |
| 승인·업무 맥락 | 정상 가능성 검토 | 초기 미확인, 담당 확인 |

## 교육용 논리와 운영 구현을 분리하기

교육용 논리는 “새 장치 로그인 후보의 계정·세션을 찾고, 이후 같은 세션에서 외부 전달 규칙 생성이 있었는지 확인”입니다. 연습에서는 15분 이내를 시험 창으로 사용할 수 있습니다. 이 숫자는 자료 이해를 위한 예이며 실제 규칙에는 정상 작업·감사 지연·인증 세션 특성을 반영합니다.

KQL 두 필터로 대상 문서를 찾은 뒤 세션과 시각을 대조할 수 있습니다. KQL 한 줄이 두 문서의 시간 관계를 자동 검증한다고 설명하지 않습니다. 실제 자동 탐지에는 제품이 제공하는 상관·시퀀스·집계 기능과 수집 구조에 맞는 구현이 필요합니다.

~~~text
dataset: "bt1-case-v2" AND event_type: "authentication"
  AND device_state: "unmanaged" AND result: "success"

dataset: "bt1-case-v2" AND event_type: "mail_rule_created"
  AND session_id: "S002"
~~~

첫 필터는 D05, 둘째는 D07을 찾습니다. 줄바꿈은 읽기 위한 것이며 각각 별도 검색으로 실행합니다. 결과의 정확한 ID는 필드·매핑과 날짜 범위가 맞는 경우에 기대합니다.

## 검증 자료를 다양하게 만들기

| 시험 | 기대 | 확인할 실패 |
| --- | --- | --- |
| 새 장치 뒤 같은 세션의 미승인 변경 | 조사 후보로 연결 | 관련 이벤트 누락 |
| 승인된 장치 교체, 변경 없음 | 정상 가능성 확인 분기 | 무조건 차단·침해 확정 |
| 다른 세션의 정상 백업 | 근거 없이 연결하지 않음 | 시각만으로 과잉 연결 |
| 설정 감사가 8분 늦게 수신 | 재조회·지연 정책으로 보완 | 최초 검색에서 영구 누락 |
| 동일 원문 재전송 | 중복 작업 방지, 근거 유지 | 조치 중복 또는 범위 손실 |
| 세션 필드 없음·조회 오류 | 자료 공백·실패로 처리 | 정상 판정으로 변환 |

제공 파일은 하나의 사례이므로 모든 테스트를 자동으로 증명하지 않습니다. 워크북에서 복사본을 만들어 정상 맥락·누락·지연 조건을 바꾸고 결과를 비교합니다. 원본 16건은 보존합니다.

## 문서와 변경을 관리하기

유스케이스에는 담당, 버전, 목표, 자료 요구, 구현 위치, 정상 예외, 검증 결과, 대응과 재검토 조건을 남깁니다. 데이터 필드나 제품 버전이 바뀌면 테스트를 다시 합니다. ATT&CK에 대응했다고 실제 탐지 범위가 완성된 것은 아닙니다. 수집 대상과 검증한 행동·조건을 구체적으로 표시합니다.

학습 활동으로 워크북의 유스케이스를 채우고 “현재 자료만으로 자동 확정할 수 없는 판단”을 두 가지 적으세요. 무단 여부와 실제 전달 범위가 별도 확인이라는 설명이 포함돼야 합니다.
