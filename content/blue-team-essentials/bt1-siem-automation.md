## SIEM의 기본 역할

SIEM은 여러 출처의 자료를 모아 검색·시각화·상관분석·경보에 사용합니다. 로그를 저장했다는 사실과 필요한 필드·시간·권한으로 검색할 수 있다는 사실은 다릅니다.

| 처리 단계 | 확인할 것 | 실패 예 |
| --- | --- | --- |
| 수집·전송 | 실제 이벤트가 원본과 수신부에 있는가 | 에이전트·경로·권한 실패 |
| 파싱 | 자료를 개별 필드로 읽었는가 | 여러 줄 결합·JSON 오류 |
| 시간 해석 | 발생 시각·시간대가 맞는가 | 수집 시각을 발생 시각으로 사용 |
| 정규화 | 출처 간 필드 의미가 같은가 | src를 서버 주소와 혼동 |
| 검색·상관 | 조건·기간·관계가 맞는가 | 과도한 필터·단일 IP 합치기 |
| 경보 | 규칙 버전·근거가 남는가 | 수집 공백을 탐지 성공으로 취급 |

원본 형식과 정규화 자료를 연결해야 오류를 되돌아볼 수 있습니다. 모든 출처를 같은 필드 이름으로 바꾸는 것만으로 같은 의미가 되지는 않습니다.

## 먼저 검색하고 그다음 탐지하기

정상 이벤트를 한 개 골라 입력부터 검색까지 추적합니다. 필드를 확인한 뒤 조건을 하나씩 넣고, 실제 원문에서 기대하는 행동이 맞는지 검토합니다. 필요할 때 시각·자산·계정·서비스 ID로 관련 자료를 연결합니다.

0개 결과는 공격 부재, 자료 미수집, 시간·권한·필드 오류를 모두 포함할 수 있습니다. 이 원인들을 구분하지 않은 규칙은 검증하기 어렵습니다.

## 자동화와 오케스트레이션

자동화는 반복 작업 하나를 실행합니다. 예를 들어 해시 검색이나 자산 소유자 조회입니다. 오케스트레이션은 여러 시스템과 단계의 입력·결과를 연결합니다. SOAR는 이런 작업과 대응 워크플로를 조직화하는 데 쓰입니다.

TIP 조회 → SIEM 검색 → 사건 보강을 연결해도 악성 여부 판단이 자동으로 증명되는 것은 아닙니다. 조회 출처·시각·실패·빈 결과를 남깁니다.

## 자동 대응의 조건

| 작업 | 필요한 통제 |
| --- | --- |
| 읽기 전용 보강 | 출처·권한·오류·중복 처리 |
| 사건 생성 | 연결 조건·기존 사건·담당 |
| 계정·호스트 제한 | 대상 확인·조치 권한·업무 영향 |
| 반복 실행 | 실행 ID·재시도·중복 조치 방지 |
| 완료 확인 | API 결과와 실제 상태 재검증 |

**작은 활동:** 한 경보에서 자동화할 조회 2개와 사람이 판단할 단계 1개를 적습니다.

**완료 기준:** SIEM 입력·탐지·조사와 자동화 실행·실제 조치 결과를 분리합니다.
