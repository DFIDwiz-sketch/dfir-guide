## 정상 DNS로 악성 목적지를 찾는 경우

프로토콜이 정상이어도 악성 사이트 이름을 해석할 수 있습니다. 질의와 응답의 원문·시각·자산을 읽고 도메인 정보와 후속 연결을 보강합니다. DNS 규격 위반과 악성 목적지 접속은 다른 질문입니다.

## 센서 위치와 과거 대응

클라이언트 → 리졸버 구간에서는 질의자를 볼 수 있지만 리졸버 → 외부 구간에서는 여러 사용자가 하나의 리졸버 주소로 보일 수 있습니다. 리졸버 로그만 있으면 직접 외부 DNS를 사용한 장비의 질의가 빠질 수 있습니다.

사건 당시의 답을 찾을 때 내부 질의·응답, 프록시·호스트 자료를 우선 봅니다. 외부 Passive DNS나 현재 조회는 관측 범위·기간이 다른 자료로 표시합니다. 현재 응답으로 과거 연결을 단정하지 않습니다.

## 정보 보강은 맥락이지 판정이 아님

| 보강 정보 | 도움이 되는 질문 | 한계 |
| --- | --- | --- |
| TLD·이름 구조 | 업무와 관련 있는 이름인가 | 특정 TLD 전체가 악성은 아님 |
| 도메인 나이·등록 정보 | 최근 만들어진 이름인가 | 새 정상 서비스·프라이버시 가능 |
| 평판·IOC | 관련 관찰이 보고됐는가 | 만료·공유 인프라·오분류 |
| 지리 정보·ASN | 어떤 네트워크와 관련되는가 | 실제 사용자·공격자 위치 보증 아님 |
| 당시 DNS 답 | 어떤 주소가 반환됐는가 | 여러 서비스가 주소 공유 가능 |

유명 공급자의 ASN이나 유효 인증서에 있다고 무조건 정상은 아닙니다. 보고서의 출처·기간과 실제 요청·파일·계정 행동을 함께 봅니다.

## DNS 자체의 악용

비승인 리졸버는 정책·관측을 우회할 수 있습니다. DNS 관리 권한 침해는 레코드를 바꿔 사용자를 다른 서버로 보낼 수 있으므로 관리 변경·계정 감사도 필요합니다.

터널링은 이름·레코드 값에 데이터를 실어 보낼 수 있습니다. 긴·고유한 이름, 반복 TXT, 많은 질의와 짧은 간격은 조사 신호이지만 CDN·텔레메트리·제품 검증도 비슷할 수 있습니다.

## IDN·유사 이름 확인하기

사람에게 보이는 Unicode 표현과 punycode 표현을 함께 보존합니다. 같은 모양의 문자가 다른 문자일 수 있습니다. example.com.other.example은 example.com의 하위 이름이 아닙니다. 도메인 경계를 정확히 읽고 등록 가능 도메인 판별에 Public Suffix List를 검토합니다.

## 작은 활동 — 두 가지 정상 대조

[가상 기록 20개](network-capstone.html)의 N011–N013과 N015를 비교합니다. 질의 타입·공통 이름·빈도·자산 역할과 필요한 호스트 자료를 적습니다.

**완료 기준:** 신호·정상 설명·보강의 한계·추가 증거를 기록하며 DNS 유출·C2를 단일 패턴으로 확정하지 않습니다.

## 최신 보강과 실무 연결

암호화 DNS는 리졸버·정책·호스트 자료로 보강합니다. 자세한 헌팅·반증·규칙화는 [DNS 악용 헌팅](dns-abuse-hunting.html), 신원·웹 연결은 [DNS 조사](dns-investigation.html)에서 수행합니다.
