## DNS에서 의심을 찾되 결론은 증거로 좁히기

DNS는 피싱·악성 인프라 연결·명령 제어·데이터 전달에 사용될 수 있습니다. 다만 희귀 도메인, 짧은 TTL, 긴 TXT, 외부 리졸버 중 어느 하나도 침해를 확정하지 않습니다. 먼저 정상 DNS 경로와 승인 정책을 확인한 뒤 비정상 후보를 찾고 다른 자료로 검증합니다.

교재의 분석 순서는 관측 위치, 평판·등록·위치 정보, 비인가 DNS, 레코드 변경, 터널링, 대체 이름 체계, IDN과 암호화 DNS입니다. 세 상세 글로 나누어 각 단서의 가치와 한계를 설명합니다.

## 분석 방법과 답하는 질문

| 방법 | 도움이 되는 질문 | 제한 |
| --- | --- | --- |
| 보유 DNS 로그 | 사건 당시 누가 어떤 답을 받았나 | 수집 범위·캐시·암호화 |
| 과거 DNS 자료 | 해당 기간의 이름·주소 관계는 | 서비스별 시간·센서 범위 |
| 등록·ASN·평판 | 운영 맥락과 알려진 사례는 | 새 등록·공유 호스팅은 정상도 많음 |
| 승인 경로 비교 | 단말이 허용된 리졸버를 썼나 | 재귀 서버·정상 예외와 구별 |
| 질의 패턴 분석 | 반복·고유 이름·타입이 이례적인가 | CDN·검증·보안 텔레메트리 오탐 |
| 단말·서비스 조사 | 어떤 앱·계정·작업이 원인인가 | 별도 수집과 담당 확인 필요 |

조회 시점의 평판이 없다는 것은 깨끗하다는 뜻이 아닙니다. 현재 DNS 응답도 사건 당시 값의 대체물이 아닙니다. 관측 사실, 외부 참고 맥락, 분석 판단을 분리합니다.

## 공통 사례의 DNS 후보

N10은 승인되지 않은 상대 203.0.113.53에 TCP/53으로 질의한 기록입니다. 정책 후보를 확인할 수 있지만 터널링을 확정할 수는 없습니다. N11~N13은 collect.notice.example 아래 서로 다른 이름의 TXT 조회입니다. 질의 내용과 빈도는 조사할 이유가 되지만 세 건으로 자료 유출을 증명할 수 없습니다. N14는 승인된 메일 테스트의 정상 TXT 예입니다.

## 암호화 DNS를 경로와 정책으로 보기

DoT·DoH·DoQ는 클라이언트와 리졸버 사이의 기밀성을 제공하는 서로 다른 방식입니다. 모든 DNS가 끝까지 암호화되었다는 뜻은 아닙니다. 허용된 관리 리졸버와 앱 설정, 리졸버 감사 기록을 연결해 필요한 관측을 확보합니다. HTTPS/443 흐름만으로 DoH를 확정하지 않습니다.

## 2022년 내용의 현재 보강

DoH의 표준 메시지는 DNS wire format이며 JSON이 필수인 방식이 아닙니다. HTTP/3·QUIC, DoQ와 ECH의 영향을 함께 고려해야 합니다. IDN의 xn-- 표기는 정상 다국어 도메인에도 사용되므로 공격으로 자동 분류하지 않습니다. 교재의 특정 대체 DNS 서비스 이름이나 차단 목록은 2022년 사례로 보고 현재의 운영 상태를 별도 확인합니다.

## 학습 활동

후보마다 단서·정상 가능성·추가 자료·조치 범위를 적습니다. 도메인·IP 차단을 검토할 때 공유 인프라의 정상 영향과 복구 경로도 포함합니다. [DNS 실습](bt2-dns-lab.html)은 가상 자료로 이 과정을 수행합니다.
