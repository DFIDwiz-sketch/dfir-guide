## 사건 당시 자료를 먼저 고정하기

질의 이름, 타입, 반환값, TTL, 응답 코드, 출발지, 리졸버, 시각과 센서 위치를 보존합니다. 현재 DNS를 다시 질의하면 주소가 바뀌었을 수 있고 분석자가 새 트래픽을 만듭니다. 과거 수집 자료부터 조사하고, 필요할 때 목적과 승인 경로에 맞춰 외부 맥락을 보완합니다.

Passive DNS 등의 과거 자료를 사용할 때는 처음·마지막 관측, 데이터 출처와 커버리지를 확인합니다. 그 서비스가 처음 본 시각은 도메인의 최초 생성일과 다릅니다. 조회 결과가 없으면 그 서비스에서 확인되지 않은 것일 수 있습니다.

## 평판 정보의 가치와 한계

| 단서 | 도움이 되는 이유 | 단독으로 부족한 이유 |
| --- | --- | --- |
| 새 등록·최근 첫 관측 | 새 인프라 후보를 좁힘 | 정상 신규 서비스도 있음 |
| 특이한 이름·TLD | 환경 기준선과 차이를 찾음 | 이름 자체는 행위가 아님 |
| ASN·호스팅 정보 | 인프라 유형·공유 여부 파악 | 행위자 국적·소유자 확정 불가 |
| IP 위치 | 대략적인 운영 맥락 | 사용자·공격자의 실제 위치 아님 |
| 알려진 평판 | 과거 사례와 연결 | 미등록·오탐·시점 차이 |
| 주소 변경 | 기간별 관계를 볼 수 있음 | CDN·부하 분산도 정상 변경 |

보고서에 “평판 서비스에서 악성으로 분류”와 “우리 자산에서 실행 확인”을 별도로 씁니다. 높은 평판 점수 또는 여러 제품의 표시가 사건의 행동 증거를 대신하지 않습니다. 정상 CDN의 공유 IP 전체를 차단하면 업무 피해가 생길 수 있어 이름·URL·기간·대상 범위를 검토합니다.

## 비인가 DNS의 기준은 승인된 역할

일반 단말이 직접 외부 UDP/TCP 53에 질의하면 승인 경로 우회 후보일 수 있습니다. 반면 조직 재귀 리졸버의 상위 질의는 정상 역할일 수 있습니다. 외부 상대를 보았다는 이유만으로 모두 같은 정책 위반으로 집계하지 않습니다. 리졸버 자산 목록과 정상 Forwarder, 예외 앱·VPN 설정이 필요합니다.

N04의 출발지는 승인 리졸버이며 N10은 단말에서 미승인 상대에 나간 기록입니다. 본 실습은 resolver_policy 필드로 정책 맥락을 제공합니다. 실무에서는 그 필드가 자동으로 존재하지 않을 수 있으므로 승인 목록과 대조합니다.

~~~spl
index=YOUR_LAB_INDEX dataset="bt2-case-v2" record_type="dns"
dest_port=53 src_ip="10.20.10.24" dest_ip!="10.20.10.53"
| table id timestamp source transport dest_ip query qtype resolver_policy
~~~

교육용 인덱스·필드 추출·2026-10-10 UTC 시간 범위를 맞췄을 때 N10이 후보로 나옵니다. UDP만 조사하면 TCP인 N10을 놓칩니다. 다수 리졸버를 승인하는 실제 환경에는 주소 하나 비교가 아니라 관리되는 목록을 적용합니다.

## 레코드 변경과 이름 체계

조직의 DNS 레코드 변경은 관리자 감사, 변경 승인, 계정과 MFA, 기존·신규 값, 전파 범위를 확인합니다. 관측 주소가 바뀌었다는 사실만으로 DNS 계정 탈취를 확정할 수 없습니다. 대체 루트·블록체인 기반 이름 해석은 표준 공용 DNS와 다른 경로를 사용할 수 있지만 사용 도구·버전·설정부터 확인합니다. 교재의 서비스 목록을 현재 목록으로 복사하지 않습니다.

권한 서버의 관리 레코드를 바꾸는 행위와 리졸버 캐시에 잘못된 응답을 넣는 행위는 다른 조사입니다. 전자는 관리 계정·변경 이력, 후자는 해당 리졸버의 응답·캐시·검증·패치 상태와 권한 서버의 실제 값을 비교합니다. 단말의 정적 이름 설정이나 미승인 리졸버도 다른 답을 만들 수 있어 변경 원인을 한 가지로 고정하지 않습니다. DNSSEC의 검증 범위·실패 처리도 함께 확인합니다.

## 조사 기록 연습

N10을 “승인 경로 우회 관측, 악성 목적 미확인”으로 기록합니다. 단말의 DNS·브라우저·VPN 설정과 설치 앱 확인을 다음 조사로 적습니다. 정책 위반과 침해 판단을 분리해야 설정 오류에 과한 차단을 하거나 악성 사용을 단순 설정 문제로 놓치는 일을 줄일 수 있습니다.
