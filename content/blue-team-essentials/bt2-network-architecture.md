## 네트워크 그림을 조사 지도처럼 읽기

네트워크 구조를 아는 목적은 장비 이름을 외우는 데 그치지 않습니다. “어느 경로를 지나고, 어디서 관측하며, 누가 정책을 적용하는가”를 설명해야 경보의 의미를 판단할 수 있습니다. 인터넷에서 서버로 들어오는 통신과 같은 스위치의 단말 사이 통신은 서로 다른 경로를 가질 수 있습니다. 외부 경계의 센서 하나가 둘을 모두 보는 것은 아닙니다.

교재의 이 장은 영역 구분, 스위치와 VLAN, 관측 지점, 방화벽, 제로 트러스트와 평면 네트워크를 연결합니다. 상세 글에서는 영역별 통신 정책을 작성한 뒤 센서의 사각지대를 찾습니다.

## 영역과 경계를 구별하기

영역은 비슷한 업무·위험·관리 요구를 가진 자산의 묶음입니다. 경계는 서로 다른 영역 사이에서 통신을 통제하거나 관찰하는 지점입니다. VLAN 번호를 붙였다고 접근 정책까지 자동으로 완성되지는 않습니다. 경계 간 라우팅, ACL, 방화벽과 호스트 정책이 실제로 적용되는지 확인해야 합니다.

| 영역 | 필요한 통신의 예 | 분석자가 확인할 내용 |
| --- | --- | --- |
| 사용자 단말 | 승인 리졸버·웹 프록시 | 직접 인터넷 DNS와 우회 경로 |
| 공개 서비스 | 외부 요청·제한된 백엔드 | 외부 입력과 서버의 후속 통신 |
| 중요 서버 | 정해진 앱·관리 경로 | 사용자 영역에서의 직접 관리 접속 |
| 관리 영역 | 관리자·점프 호스트 | 계정·장치·승인 작업의 일치 |
| 게스트·IoT | 제한된 외부 서비스 | 내부 서버 접근·새 장치 |
| 클라우드·SaaS | 업무 API·접속 서비스 | 별도 감사 로그와 외부 통신 경계 |

## TAP와 SPAN이 답하는 질문

TAP는 설치된 링크의 신호를 관측 장비 쪽으로 복제합니다. SPAN은 스위치가 지정된 포트·VLAN 등의 트래픽을 미러 포트로 보냅니다. 둘 다 선택한 위치와 구성의 영향을 받습니다. 스위치 위쪽 링크의 TAP는 그 링크를 지나지 않는 같은 VLAN의 단말 간 통신을 놓칠 수 있습니다. SPAN도 대상 포트가 빠지거나 출력 용량을 넘으면 자료가 누락될 수 있습니다.

탐지 경보가 없다는 사실을 “공격이 없었다”로 바꾸기 전에, 해당 통신이 수집 지점을 통과했는지 먼저 확인합니다. 학습 자료 N22에는 센서 드롭 지표와 제한된 PCAP 범위가 기록되어 있습니다.

## 우리 조사 환경에 연결하기

Core와 Sensor는 각자의 방화벽으로 접근을 제한하고, 대상망 쪽 TAP에서 Sensor가 수동으로 트래픽을 받습니다. 분석가는 Core 쪽의 허용된 관리 경로를 사용합니다. 수동 캡처 인터페이스를 대상망 관리 접속 경로와 혼동하지 않습니다.

네트워크 자료는 계속 색인하며 Splunk·Arkime·Suricata·Zeek에서 조사합니다. 단말 자료는 필요할 때 Velociraptor Hunt로 수집하고 Hayabusa로 Windows 이벤트를 분석합니다. 네트워크 센서가 단말의 프로세스 실행까지 상시 수집한다고 가정하지 않습니다.

## 2022년 설명에서 보강할 점

제로 트러스트는 내부 위치만으로 접근을 신뢰하지 않고 사용자·장치·자원·상황에 따른 접근 판단을 설계하는 원칙입니다. 망 분리는 유용하지만 그 원칙 전체를 대신하지 않습니다. 교재에 등장하는 EMET 같은 과거 제품을 현재 도입 대상으로 옮기기보다 현재 지원되는 보호 기능과 운영 정책을 검토합니다.

## 학습 활동

자신의 네트워크에서 사용자→리졸버, 사용자→서버, 서버→인터넷, 분석가→Core의 경로를 그립니다. 각 경로에 통제 지점·관측 지점·자료 출처·사각지대를 적습니다. 두 상세 글의 표를 활용하면 센서를 추가할 이유도 설명할 수 있습니다.
