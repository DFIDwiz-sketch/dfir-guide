## 실습 목표와 준비

이 실습은 경보를 사건에 연결하고 작업·관측값·분석·조치 결과를 구분해 기록하는 연습입니다. 교재의 TheHive 실습 제목에 대응하지만 원본 Lab Workbook을 재현하지 않습니다. [공통 사례](downloads/blue-team-day1-case.ndjson)와 [워크북](downloads/blue-team-day1-workbook.md)을 사용하며, 제품이 없어도 동일한 데이터 구조를 Markdown으로 작성할 수 있습니다.

현재 TheHive 5는 라이선스 체계를 제공합니다. 무료 Community도 라이선스 요청과 조건 확인이 필요하므로 2022년의 무료 오픈소스 설명을 그대로 설치 조건으로 사용하지 않습니다. 기존 승인된 교육 환경에서 버전·역할·사용 가능한 기능을 확인하세요. 실습 목적 때문에 새 유료 서비스를 구매할 필요는 없습니다.

## 사례를 먼저 읽고 객체를 정하기

| 자료 | 사건 관리에 넣는 위치 | 남길 설명 |
| --- | --- | --- |
| D06·D08 | 관련 경보 또는 설명의 경보 목록 | 원문 D05·D07과 관계 |
| D05·D07 | 타임라인·근거 | 같은 계정·세션의 행동 |
| learner·S002·192.0.2.80 | 관측값 또는 구조화된 사건 필드 | 값의 출처·역할, 악성 단정 금지 |
| D11·D12 | 확인 작업의 기록 | 별도 확인 채널·미승인 판단 |
| D13·D14 | 대응 작업의 요청·결과 | 요청과 감사 성공을 구별 |
| D15·D16 | 남은 작업·공백 | 전달·다른 세션·장치 자료 한계 |

TheHive가 지원하는 관측값 유형은 환경의 설정에 따라 확인합니다. 계정·세션을 지원 유형으로 직접 넣을 수 없다면 사건 필드나 설명에 기록합니다. 타입을 맞추려고 세션 ID를 도메인이나 IP로 가장하지 않습니다.

## 1단계 · 사건 만들기

교육용 제목 `LAB-BT1-20261008 · 계정 세션과 메일 규칙 확인`을 사용합니다. 설명에는 현재 판단, 영향 범위와 미확인 질문을 적습니다. 사건 담당과 조직에서 정의한 심각도를 정합니다. 이 자료의 P2는 학습용 정의이므로 제품 기본 심각도 숫자와 자동으로 같다고 보지 않습니다.

실제 메뉴 이름은 버전과 권한에 따라 다릅니다. 생성 권한이 없으면 기록지를 작성하고 교육 운영자에게 인계를 연습하면 됩니다. 원문은 파일명·레코드 ID·시간 범위로 찾을 수 있게 연결합니다.

## 2단계 · 작업과 완료 조건 만들기

| 작업 | 담당 역할 | 완료 조건 |
| --- | --- | --- |
| 경보·원문 연결 | 분석가 | D06→D05, D08→D07과 검색 조건 기록 |
| 사용자·운영자 확인 | 분석가·메일 운영자 | D11·D12의 확인 내용과 출처 기록 |
| 전달 범위·다른 세션 조사 | 메일 운영자 | 조회 기간·자료·결과 또는 실패 이유 |
| 승인된 조치와 효과 확인 | 조치 권한 담당 | 대상·승인·요청·감사·현재 상태 |

작업마다 현재 상태와 기한을 정합니다. 제공 자료에 없는 메시지 추적을 완료로 표시하지 않습니다. D14는 세션 폐기 작업의 한 근거이고, 사건 전체 종결 근거는 아닙니다.

## 3단계 · 관측값과 분석 결과 기록

관측값에는 실제 값과 출처를 적고, 악성 IOC 판정과 관측 사실을 구별합니다. 내부 데이터 또는 가상 자료를 외부 분석 서비스에 보내기 전에 조직의 공유 정책을 확인합니다. 이 교육용 IP·도메인의 외부 평판을 조회해 실제 공격 정보를 얻는 것은 실습 목표가 아닙니다.

Cortex Analyzer는 조회·분석 결과를 보강하는 역할이고 Responder는 작업·조치를 수행할 수 있는 역할입니다. 제품에서 같은 통합 화면에 있어도 권한과 부작용이 다릅니다. 실습에서는 결과 기록을 작성하는 것으로 충분하며 실제 차단·계정 변경을 실행할 필요가 없습니다.

## 4단계 · 작업 결과와 인계 검토

확인된 D11·D12와 미확인 메시지 범위를 나눠 사건 요약을 갱신합니다. D09·D10의 내부 PC 활동은 정상 맥락과 S002 관련 근거 부재를 적습니다. D16의 호스트 공백을 남기고 다른 자료로 가능한 조사 범위를 제시합니다.

기대 결과는 사건 하나, 연결된 경보 두 개, 결과 또는 미완료 이유가 있는 작업 네 개, 관측값의 맥락, 미확인 질문입니다. 동료가 같은 파일에서 근거를 찾고 다음 작업을 시작할 수 있으면 구조가 충분히 명확한 것입니다.

## 자주 생기는 문제

관측값 중복은 같은 값의 여러 출처와 맥락을 잃지 않는 방식으로 처리합니다. 담당 없이 작업을 만들면 대기 상태가 계속될 수 있습니다. 제품 UI에서 종결 버튼을 누를 수 있다고 조사 완료 조건을 충족한 것은 아닙니다. 필수 작업과 후속 담당을 먼저 확인합니다.
