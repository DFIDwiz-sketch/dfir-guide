## 사건 설명과 작업 기록은 역할이 다르다

사건 설명은 현재 알려진 범위와 판단을 요약합니다. 작업 기록은 특정 확인이나 조치를 누가 언제 어떤 조건으로 수행했는지 남깁니다. 사건 설명에 모든 실행 결과를 덮어쓰면 판단이 어떻게 바뀌었는지 사라집니다. 원문과 작업 기록을 유지하고 요약을 갱신해야 합니다.

관측값은 IP·도메인·계정·해시처럼 검색과 관련 분석의 대상이 되는 값입니다. 관측값을 등록했다고 자동으로 악성이라는 뜻은 아닙니다. 같은 값의 정상·악성 사용 맥락이 다를 수 있으므로 역할·출처·확신과 관련 이벤트를 함께 기록합니다.

## 플레이북의 뼈대

플레이북에는 목적, 적용 조건, 필요한 입력, 담당·권한, 필수·조건부 작업, 종료 조건, 실패 처리, 기록 위치와 검토 버전이 필요합니다. 모든 장치·계정 사건에 하나의 문서를 적용하면 자료와 조치 권한이 달라 잘못된 작업을 수행할 수 있습니다. 적용 범위를 먼저 정합니다.

다음은 교육용 계정·메일 사건 플레이북입니다. 실제 변경 명령이나 무조건 차단 자동화가 아니라, 판단과 작업의 관계를 배우는 예입니다.

| 순서 | 작업 | 의존성과 조건 | 결과 |
| --- | --- | --- | --- |
| 1 | 경보·원문 대조 | 관련 이벤트 ID와 시간 범위 확보 | 규칙 일치와 원문 |
| 2 | 계정·세션·업무 확인 | 원문 대상 식별 후 수행 | 정상 가능성·중요도 |
| 3 | 관련 설정과 다른 세션 조사 | 감사 자료와 검색 권한 필요 | 확인된 범위와 공백 |
| 4 | 우선순위·대응 결정 | 진행 상태·영향·승인 기준 확인 | 이유와 승인자 |
| 5 | 승인된 조치 실행 | 조치 권한, 대상 식별 검증 | 요청 ID·실행 결과 |
| 6 | 효과와 남은 위험 확인 | 실행 결과 뒤 재조회 | 실제 상태·남은 질문 |
| 7 | 종결·후속 작업 결정 | 필수 작업 결과와 범위 검토 | 종결 이유 또는 계속 조사 |

사용자가 승인된 새 장치라고 확인하고 관련 정책 위반도 없으면 다른 분기로 갈 수 있습니다. 감사 조회가 실패했다면 “정상” 분기가 아니라 자료 확보·인계 분기로 가야 합니다. 필수 정보 부재와 정상 결과를 같은 값으로 처리하면 실패를 숨기게 됩니다.

## 필수·조건부·선택 작업을 정하기

원문과 대상 확인은 보통 모든 사건에서 필요합니다. 실제 메시지 전달 범위 확인은 전달 설정이 관련될 때 필요한 조건부 작업입니다. 추가 외부 평판 조회는 판단에 도움이 될 때 수행할 수 있는 선택 작업입니다. 무조건 외부 조회를 하면 민감한 관측값이 조직 밖으로 나갈 수 있으므로 공유 권한을 확인합니다.

작업을 체크박스만으로 관리하지 않습니다. “완료”에는 확인한 조건과 결과가 있어야 합니다. “관련 메시지 없음”이라는 결과에는 기간·계정·조회 조건과 수집 상태를 넣습니다. 자료가 없는 경우에는 이유와 다음 담당을 넣습니다.

## 플레이북 검토 활동

공통 사례의 D13을 읽고 조치 작업을 완료로 표시한 뒤 D14·D15·D16을 읽어 그 표시가 충분한지 검토하세요. 세션 폐기 요청과 사건 전체의 해결을 분리할 수 있어야 합니다. 마지막으로 감사 API 실패, 사용자 연락 불가, 다른 계정 발견이라는 세 상황에 대한 분기를 워크북에 추가합니다.
