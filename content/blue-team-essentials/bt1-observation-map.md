## 질문을 먼저 쓰면 자료 선택이 쉬워진다

“무슨 로그를 모을까?”부터 시작하면 제품이 제공하는 자료를 모두 모으기 쉽습니다. 대신 “어느 계정이 어떤 세션으로 메일 설정을 바꿨는가?”처럼 조사 질문을 먼저 쓰세요. 필요한 것은 계정·세션·설정 변경의 감사 자료입니다. 내부망 패킷만으로는 SaaS 내부 변경의 실행자를 확인하지 못할 수 있습니다.

네트워크에서는 데이터의 이동을, 호스트에서는 실행과 상태를, 클라우드·SaaS에서는 제어면과 서비스 활동을 보는 방식으로 접근합니다. 이 구분은 딱 잘라 나뉘는 제품 분류가 아니라 자료가 답할 수 있는 질문을 정리하는 방법입니다.

## 자료별로 확인 가능한 범위

| 자료 | 좋은 조사 질문 | 자료 하나로 부족한 부분 |
| --- | --- | --- |
| 흐름 기록 | 누가 어디에 언제 얼마나 연결했는가? | 상세 응용 내용·프로세스 |
| PCAP | 관측 지점에서 어떤 패킷이 오갔는가? | 암호화된 본문, 관측 밖 경로 |
| DNS·HTTP 프로토콜 로그 | 이름 조회·요청·응답 특징은 무엇인가? | 그 요청을 만든 사용자와 실행 맥락 |
| 프로세스·서비스 자료 | 무엇이 어떤 사용자·부모 아래 실행됐는가? | 누락된 과거 실행·원격 서비스 내부 활동 |
| 인증 로그 | 어떤 계정이 어떤 결과로 인증했는가? | 실제 사람의 의도·인증 이후 모든 행위 |
| SaaS 감사 | 누가 어떤 객체·권한·설정을 바꿨는가? | 미지원 기능, API 제한·보존 밖 활동 |

같은 시각과 IP가 나타나도 바로 동일 행동으로 연결하지 않습니다. NAT·프록시·공유 계정·다중 세션 때문에 식별자가 일대일 관계가 아닐 수 있습니다. 가능하면 세션, 호스트, 계정, 요청 ID처럼 출처가 정의한 식별자를 함께 사용합니다.

## 공통 사례를 자료에 배치하기

D05는 `learner`의 세션 S002 로그인입니다. D07에는 같은 세션과 출발 IP가 있어 메일 설정 변경의 연결 근거가 됩니다. 반면 D09·D10은 LAB-PC01의 DNS·백업입니다. 세션 S001의 정상 활동과 가까운 시각에 있지만 S002와 연결하는 근거는 없습니다.

여기서 “백업 프로세스가 있으므로 정보가 유출됐다”는 결론은 성립하지 않습니다. 프로세스의 승인 상태와 작업 일정부터 확인하고 실제 파일·전송 자료가 있는지 따로 봅니다. “LAB-PC01이 정상이라 S002도 정상”이라는 반대 결론도 성립하지 않습니다. 사건이 계정 중심인지 장치 중심인지가 다르기 때문입니다.

## 클라우드 서비스 유형에 따라 달라지는 책임

IaaS에서 조직이 VM을 운영하면 호스트 OS와 워크로드 자료를 직접 수집할 여지가 큽니다. PaaS와 서버리스에서는 플랫폼이 제공하는 실행·접근·관리 감사에 더 의존합니다. SaaS에서는 서비스의 로그인·관리·사용자 활동 API와 라이선스·역할·보존 기능을 확인해야 합니다. 모든 서비스에서 같은 로그와 원문을 얻을 수 있다고 가정하지 않습니다.

제어면 기록은 자원·정책·권한을 바꾸는 관리 활동을 보여주고, 데이터 접근 기록은 객체 읽기·쓰기 같은 활동을 보여줄 수 있습니다. 실제 제공 범위와 활성화 상태는 제품별로 확인합니다. 제어면 로그만 보관하면서 데이터 열람 범위도 모두 안다고 설명하면 조사 범위를 과장하게 됩니다.

## 온디맨드 수집과 지속 수집의 차이

조사 시점의 프로세스 목록은 현재 상태입니다. 과거 프로세스 이벤트는 미리 설정한 로깅과 보존이 있어야 확보할 수 있습니다. 나중에 호스트 수집 도구를 실행해도 이미 사라진 프로세스나 기록하지 않은 명령줄이 모두 복원되지는 않습니다. 수집 결과에는 실행 시각·도구·대상·오류·자료 기간을 함께 남깁니다.

계속 수집하는 에이전트도 무조건 완전하지 않습니다. 정책이 꺼졌거나 필드가 빠지거나 수집 서버가 밀릴 수 있습니다. “설치됨”, “수집 중”, “필요한 필드가 들어옴”, “검색 가능함”은 각각 확인할 상태입니다.

## 관측 지도 작성 활동

워크북의 관측 지도에 계정 로그인, 메일 규칙 변경, 호스트 실행, 실제 메시지 전달을 넣으세요. 각 질문마다 자료와 기간·소유자·공백을 적습니다. 마지막 질문은 제공 사례에 직접적인 메시지 전달 자료가 없으므로 “추가 수집 필요”가 됩니다. 필요한 자료를 구체적으로 요청하는 것이 이 활동의 결과입니다.
