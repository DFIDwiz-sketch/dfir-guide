## 분류는 빠른 결론보다 다음 작업을 정하는 과정이다

초기 분류의 목적은 완전한 포렌식 보고서를 만드는 것이 아닙니다. 관련성·우선순위·담당·다음 확인을 정하는 것입니다. 경보가 어떤 자산과 계정에 영향을 주며 진행 중인 피해 가능성이 있는지 확인하고, 충분한 근거가 없으면 그 상태를 명시합니다.

핵심 계정의 활성 세션, 외부 전달 설정, 사용자의 부인이 이어지면 빠른 대응 인계가 필요할 수 있습니다. 반면 승인된 배포 작업에 따른 단일 경보는 정상 맥락을 확인한 뒤 분류할 수 있습니다. 정해진 숫자 임계값만으로 두 상황을 동일하게 처리하지 않습니다.

## 초기 확인에 필요한 다섯 묶음

1. **원문:** 경보 ID, 규칙, 관련 이벤트, 발생·수신 시각을 확인합니다.
2. **대상:** 자산·계정·세션의 정확한 식별자와 중요도를 확인합니다.
3. **맥락:** 장치 상태, 업무 일정, 승인된 예외와 사용자 확인을 구합니다.
4. **관계:** 같은 계정·세션·대상에서 이전과 이후의 활동을 찾습니다.
5. **행동:** 담당, 우선순위, 추가 자료, 긴급 조치 조건을 정합니다.

동일 계정 검색 결과가 모두 같은 사건은 아닙니다. 세션 S001의 정상 활동과 S002의 미승인 변경을 분리하고, 관련 없는 LAB-PC01의 백업도 분리합니다. 사건을 크게 묶는 것과 근거 없이 모든 활동을 공격으로 만드는 것은 다릅니다.

## 공통 사례의 단계별 분류

| 받은 자료 | 현재 판단 | 다음 작업 |
| --- | --- | --- |
| D05·D06 | 새 미관리 장치 로그인, 무단 여부 미확인 | 사용자·승인된 장치 변화·다른 활동 확인 |
| D07·D08 | 같은 세션의 외부 전달 설정으로 영향 가능성 증가 | 업무 예외와 실제 설정·전달 감사 확인 |
| D11 | 사용자가 S002 활동을 부인 | 신뢰 가능한 별도 확인, 운영자 인계 |
| D12 | 운영자가 설정을 미승인으로 확인 | 승인된 세션·규칙 조치와 범위 조사 |
| D13·D14 | 요청 뒤 서비스 감사상 세션 폐기 성공 | 다른 세션·규칙 제거·실제 전달 범위 확인 |

D11의 사용자 확인도 출처와 확인 방식을 기록해야 합니다. 공격자가 이용할 수 있는 의심 세션에서 받은 답변만으로 신뢰를 결정하지 않습니다. 이 교육 자료의 D11은 별도 지원 채널 확인이라는 가정이 워크북에 명시되어 있습니다.

## 우선순위의 근거를 문장으로 남기기

교육용 기록에서는 P2를 “미승인 활동이 확인되어 신속한 운영자 대응이 필요한 상태”로 정의합니다. 이는 보편적 표준이 아닙니다. 실제 조직은 영향·긴급도·서비스 약속에 맞춰 우선순위를 정합니다. 단계 이름보다 이유가 중요합니다.

~~~text
우선순위 근거:
새 장치 경보만으로 침해를 확정하지 않았음.
같은 세션의 전달 설정, 사용자 부인, 미승인 확인이 추가되어
계정의 진행 중인 오용 가능성과 메일 영향 확인 필요성이 커졌음.
현재 자료로 유출 메시지 수나 다른 계정 영향은 확인하지 못함.
~~~

## 공통 큐와 전문 분석 화면의 역할

공통 큐에는 상태·책임자·다음 작업·기한을 둡니다. 세부 패킷은 패킷 분석 도구에서, 프로세스 관계는 호스트 도구에서, 메시지 전달은 서비스 감사에서 확인할 수 있습니다. 사건 기록에는 각 결과의 출처와 조회 조건을 연결합니다. 화면 URL만 남기면 권한·기간·세션이 달라 재현되지 않을 수 있으므로 핵심 식별자도 남깁니다.

중복 경보를 연결할 때는 대표 사건과 관련 경보 ID를 유지합니다. 자동 종결 기준에는 적용 범위·예외·검토 담당이 필요합니다. 반복 건수를 줄였다는 이유만으로 탐지 성과가 향상됐다고 보지 않습니다.

## 인계 활동

워크북에 원문 ID, 확인된 사실, 미확인 영향, 자료 공백, 다음 담당을 적으세요. 다음 담당은 “확인 부탁” 대신 “세션 S002와 같은 계정의 다른 활성 세션, 전달 규칙 현재 상태, 메시지 추적을 확인”이라는 요청을 받아야 합니다. 완료 여부를 판단할 질문이 구체적이면 인계가 더 빠르고 재현 가능해집니다.
