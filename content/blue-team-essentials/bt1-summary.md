## 1일차의 연결을 다시 확인하기

SOC의 임무는 보호할 업무와 줄일 영향을 정합니다. 관측 지도는 그 업무에 관련된 행동을 어느 자료에서 볼 수 있는지 설명합니다. 탐지는 조사 후보를 만들고, 분류는 우선순위·담당·다음 질문을 정합니다. 사건 관리에는 근거·작업·결정·조치를 남깁니다. 인텔리전스는 값에 맥락을 붙여 결정을 돕고, SIEM·자동화는 반복 가능한 검색과 작업 연결을 지원합니다.

각 요소가 분리되면 경보는 많지만 대응은 느릴 수 있습니다. 중요한 계정인데 감사 자료가 없거나, 경보를 확인했는데 조치 권한이 없거나, 조치를 요청했는데 효과를 확인하지 않은 상태가 생깁니다. 1일차의 결과물은 도구 이름 목록이 아니라 이런 단절을 설명하고 메우는 기록입니다.

## 공통 사례의 근거 사슬

| 자료 | 확인 가능한 내용 | 한계·다음 확인 |
| --- | --- | --- |
| D05·D06 | 새 미관리 장치 로그인과 조건 경보 | 무단 사용 여부는 초기 미확인 |
| D07·D08 | 같은 세션의 외부 전달 설정과 정책 경보 | 실제 메시지 전달 범위는 없음 |
| D11·D12 | 사용자 부인과 미승인 설정 확인 | 다른 세션·계정 범위는 미확인 |
| D13·D14 | 폐기 요청과 서비스 감사 성공 | 규칙·토큰·다른 세션 확인 필요 |
| D09·D10 | 내부 PC의 정상 맥락 자료 | S002 공격 행동으로 연결할 근거 없음 |
| D15·D16 | 남은 질문과 호스트 자료 공백 | 사건 전체 종결은 아직 아님 |

타임라인에서는 원문 발생 시각을 사용하고 D07의 수신 지연도 따로 적습니다. 기록 종류를 구별해 사건 확인 메모와 보안 이벤트를 같은 행동 건수로 세지 않습니다. “없는 자료”도 조사 범위를 정하는 중요한 정보입니다.

## 마지막 인계 문서의 예

~~~text
판단: learner 계정의 S002 세션과 미승인 메일 규칙 변경을 조사 중.
근거: D05·D07의 계정/세션, D11 사용자 부인, D12 운영자 확인.
조치: D13 폐기 요청 뒤 D14 서비스 감사 성공을 기록함.
분리: D09·D10은 내부 PC 정상 활동이며 S002 연관 근거 없음.
미확인: 실제 전달 메시지, 다른 세션·토큰, 규칙 제거 현재 상태.
공백: S002 미관리 장치의 호스트 자료 없음(D16).
다음 작업: 메일 운영자가 범위·현재 설정·추가 세션을 조회하고
           확인된 결과와 실패·공백을 사건 기록에 남김.
~~~

이 문장은 사건 전체를 완전 해결로 표현하지 않습니다. 승인된 조치 성공과 남은 조사 범위를 함께 전달합니다. 초기 접근 방식이나 공격자 귀속도 제공 자료로 확정하지 않습니다.

## 작성한 결과물을 검토하기

| 결과물 | 확인할 품질 |
| --- | --- |
| SOC 임무·권한 | 보호 업무, 제외 범위, 조치 승인자가 명확한가? |
| 관측 지도 | 중요한 행동에 자료·기간·담당·공백이 있는가? |
| 경보 분류 | 조건 일치와 무단 여부를 구별했는가? |
| 사건 기록 | 작업 결과·근거·미완료 이유가 연결되는가? |
| 정보 카드 | 값의 역할·출처·시각·공유·사용 조건이 있는가? |
| 유스케이스 | 자료 요구·정상·실패·지연 시험이 있는가? |
| 자동화 | 조회 실패·중복·승인·효과 확인을 처리하는가? |

정의만 다시 쓰기보다 자신의 작성물에서 해당 항목을 찾으세요. 설명할 수 없는 빈칸은 다음 학습이나 운영 개선의 대상입니다. 모든 도구를 설치했어도 이 결과물이 없으면 개념을 운영으로 연결하지 못한 것입니다.

## 2022년 교재와 현재 보강의 차이

운영 기본기와 도구 역할은 유지하면서 계정·토큰·SaaS·클라우드 관측을 추가했습니다. NIST Rev. 3, 현재 로깅·SIEM·SOAR 지침, TheHive 라이선스, MISP 공유·탐지 사용, Elastic의 현재 업로드·KQL 문서, 위협 이름 변경과 역사 사례의 날짜를 반영했습니다. 각 글의 공개 참고자료에서 확인할 수 있습니다.

## 다음 실습과 2일차로 이어가기

마지막 Elastic 실습에서는 16건을 직접 검색하고 ID와 종류별 수를 대조합니다. 이후 2일차에서는 DNS·HTTP·메일·캡처 자료가 어떤 질문에 답하는지 더 자세히 살펴봅니다. “통신이 보였다”와 “호스트에서 실행됐다”를 구별하는 1일차의 관점을 유지하세요.
