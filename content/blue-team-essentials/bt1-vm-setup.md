## 실습 환경의 목적부터 구분하기

교재의 VM Setup은 이후 도구 실습을 위한 환경 준비입니다. 이 사이트에서는 교재 VM 대신 새로운 교육용 자료를 사용합니다. 따라서 원본 이미지가 없어도 로그 파일과 기록지로 개념 학습을 시작할 수 있습니다. TheHive·MISP·Elastic 설치는 기능별 연습을 위해 선택하는 단계이며 세 제품을 모두 설치해야 첫 장을 읽을 수 있는 것은 아닙니다.

| 학습 환경 | 할 수 있는 활동 | 추가로 필요한 준비 |
| --- | --- | --- |
| 파일만 사용하는 환경 | 시간순 정렬, 근거 구분, 사건·정보 양식 작성 | 텍스트 편집기 또는 Python 3 |
| 승인된 기존 교육 환경 | 사례 입력, 검색, 작업 배정과 정보 맥락 확인 | 계정·권한·버전·데이터 저장 위치 확인 |
| 별도 실습 VM | 제품 설치와 연동까지 확장 | 제품 공식 설치 지침, 자원·네트워크·백업 계획 |

현재 TheHive의 라이선스나 Elastic의 메뉴·권한은 2022년 화면과 다를 수 있습니다. 제품별 실습 글에서 현재 확인한 문서를 연결합니다. 오래된 VM의 운영체제와 제품 버전을 최신 운영 환경의 기준으로 삼지 않습니다.

## 네트워크 모드가 달라지면 관측도 달라진다

가상화 제품마다 이름과 동작이 다르지만, 일반적으로 NAT는 VM의 외부 통신을 호스트 경로로 보내고, 브리지 연결은 VM을 연결된 네트워크의 장치처럼 보이게 합니다. 호스트 전용·내부 네트워크는 실습 범위를 제한하는 데 사용할 수 있습니다. 정확한 접근 가능성은 제품 설정과 호스트 방화벽에 따라 달라집니다.

단순히 “VM이라 격리됐다”라고 생각하지 말고 VM → 호스트, VM → 다른 VM, VM → 인터넷, 외부 → VM의 경로를 적으세요. 이 실습에는 실제 악성코드 실행이나 공격용 외부 통신이 필요 없습니다. 교육용 로그를 올릴 수 있는 최소한의 경로면 충분합니다.

## 준비 상태를 기록하는 순서

1. 실습 목적과 사용할 제품을 정합니다. 파일 분석부터 시작하면 제품 없이도 진행할 수 있습니다.
2. OS·도구 버전, 시간대, CPU·메모리·디스크 여유 공간을 기록합니다. 제품의 현재 요구 사항은 공식 설치 문서에서 확인합니다.
3. 데이터 저장 위치와 분석 결과 저장 위치를 구분합니다. 원본 파일은 수정하지 않고 복사본으로 실험합니다.
4. VM을 사용하면 정상 상태의 스냅샷을 만듭니다. 스냅샷은 해당 VM 복원 수단이며 외부 제품의 데이터나 별도 저장소까지 자동으로 복구하지는 않습니다.
5. [사례 로그](downloads/blue-team-day1-case.ndjson)를 읽어 16행이 각각 JSON 객체인지 확인합니다. 세 제품에 같은 자료를 그대로 가져오는 것이 아니라 역할에 맞춰 이벤트·사건·정보를 선별합니다.

## 파일만으로 시작하는 첫 확인

파일이 있는 폴더에서 다음을 실행합니다. Python 3을 사용하며 네트워크 요청이나 제품 설정 변경은 하지 않습니다.

~~~python
import json
from collections import Counter

with open("blue-team-day1-case.ndjson", encoding="utf-8") as f:
    records = [json.loads(line) for line in f if line.strip()]

print("records:", len(records))
print("types:", dict(Counter(r["record_type"] for r in records)))
print("ids unique:", len({r["id"] for r in records}) == len(records))
print("datasets:", sorted({r["dataset"] for r in records}))
~~~

기대 결과는 레코드 16건, 중복 없는 ID, `bt1-case-v2`라는 데이터셋입니다. 종류별 수는 Elastic 실습에서 대조합니다. 실패하면 오류의 행 번호, 파일 인코딩, 내려받은 파일 이름을 먼저 확인하세요. 설치를 다시 하는 것은 파일 형식 오류를 해결하지 못합니다.

## 환경 문제와 사건을 혼동하지 않기

검색 결과가 없을 때는 먼저 입력 성공, 시간 범위, 필드 매핑과 접근 권한을 확인합니다. 로그 날짜가 2026-10-08인데 기본 검색이 최근 15분이면 기록이 사라진 것처럼 보입니다. 시간대가 다르면 표시 시각은 달라지지만 동일한 UTC 시각을 나타낼 수 있습니다. 데이터가 없다는 주장 전에 이 조건을 기록해야 합니다.

완료 결과물은 환경표와 파일 검증 결과입니다. 다음 실습에서 문제가 생기면 환경표에 적힌 버전·권한·시간대를 기준으로 원인을 좁혀갑니다.
