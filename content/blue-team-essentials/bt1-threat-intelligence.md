## 정보에서 인텔리전스로

IP·해시 목록은 분석의 재료입니다. 위협 인텔리전스는 요구 사항에 맞춰 출처·행동·조건·관련성을 검토해 방어 결정에 도움이 되도록 만드는 정보입니다.

“이 도메인이 목록에 있다”와 “우리 자산에서 언제 어떤 행동과 연결됐는가”는 다릅니다. 후자는 기간·자산·자료·정상 설명을 추가해야 답할 수 있습니다.

## 위협을 판단할 관점

행위자의 의도, 행동을 수행할 능력, 실제 접근 가능한 기회를 검토합니다. 위협그룹 이름을 아는 것만으로 조직이 노출됐다는 결론을 내리지 않습니다. 사용하는 제품·계정·업무와 관련 있는 조건을 먼저 찾습니다.

## TIP에서 관리하는 정보

| 정보 | 필요한 맥락 |
| --- | --- |
| 도메인·IP·URL·해시 | 유형·출처·관찰 기간·신뢰 |
| 보고서·사례 | 직접 관찰·추정·발표일·사건 기간 |
| 행동·기법 | 필요한 권한·자료·정상 대조 |
| 관계 | 어떤 값이 어떤 사건·도구와 관련되는가 |
| 내부 관찰 | 우리 자료의 시각·자산·원문 |
| 공유 조건 | 수신자·배포 범위·만료·처리 정책 |

자동 Feed는 입력을 빠르게 가져오는 기능입니다. 데이터가 최신인지, 중복·오분류·공유 인프라가 있는지는 별도 평가합니다. 피드 수가 늘어도 분석 품질이 자동으로 올라가지는 않습니다.

## MISP의 기본 용어

Event는 관련 정보의 묶음, Attribute는 개별 값·유형·설명입니다. Object는 관계 있는 값을 구조화하고 Tag·Taxonomy는 분류와 맥락을 붙입니다. Galaxy는 위협 행위자·도구·기법 등 지식 관계를 표현하는 데 쓰이며 Sighting은 관찰·오탐·만료 등의 정보를 기록하는 구조입니다.

동일 값의 상관관계는 분석의 시작입니다. 동일 공격자나 동일 침해를 자동으로 의미하지 않습니다. to_ids 같은 탐지 활용 표시와 악성 판정·배포 권한도 구분합니다.

## 공유와 수명

TLP 등 제공자의 공유 조건을 유지하고 원문 출처·first/last seen·검토일을 붙입니다. IOC 조회는 조사, 탐지 규칙 적용, 차단 정책과 서로 다른 결정입니다. IP가 재할당됐거나 공유 CDN이면 넓은 차단이 정상 업무에 영향을 줄 수 있습니다.

**작은 활동:** 예제 도메인에 출처·시각·맥락·신뢰·공유 범위·후속 검색을 넣은 정보 카드를 만듭니다.

**완료 기준:** IOC 값과 인텔리전스 판단, TIP 저장과 실제 대응을 구분합니다.

## 최신 보강과 실무 연결

현재 공유 기준은 TLP 2.0이며 예전 WHITE 대신 CLEAR가 사용됩니다. [인텔리전스 운영](threat-intelligence-operations.html)의 공유·만료 설명과 [실습 1.2](bt1-misp-lab.html)를 연결합니다.
