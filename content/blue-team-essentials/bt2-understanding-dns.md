## DNS는 주소록보다 넓은 분산 정보 시스템이다

DNS는 이름에 연결된 주소·메일 서버·서비스 위치·검증 정보 등을 조회합니다. 이름과 IP는 일대일 관계가 아닙니다. 하나의 이름에 여러 주소가 있을 수 있고 여러 이름이 같은 CDN·공유 호스팅 주소를 사용할 수 있습니다. 사건 당시 응답과 현재 응답도 다를 수 있습니다.

교재의 흐름에 따라 역할과 조회 경로, 정방향·역방향 레코드, MX·TXT·CNAME·SRV, 내부 DNS를 학습합니다. 세 상세 글은 조회 원리, 레코드 읽기, 관측과 단말 연결을 각각 다룹니다.

## 클라이언트에서 권한 서버까지

| 역할 | 동작 | 조사에서 주의할 점 |
| --- | --- | --- |
| Stub Resolver | 앱·OS에서 조회를 시작 | 브라우저·OS 설정이 다를 수 있음 |
| Forwarder | 다른 리졸버로 요청 전달 | 상위 관측에서는 원래 단말이 가려짐 |
| Recursive Resolver | 필요한 위임을 따라 답을 얻음 | 캐시가 있으면 외부 질의가 생략됨 |
| Authoritative Server | 담당 zone의 데이터를 응답 | 조직 소유·관리 범위를 따로 확인 |

한 서버가 여러 역할을 수행할 수 있습니다. 캐시가 없을 때 재귀 리졸버는 루트·상위 zone·담당 권한 서버의 위임을 따라갑니다. 매번 모든 단계가 반복되지는 않습니다. Linux와 Windows의 캐시도 OS 서비스·앱·구성에 따라 달라집니다.

## 레코드를 질문에 맞춰 해석하기

A·AAAA는 주소, CNAME은 별칭, PTR은 역방향 이름, MX는 수신 메일 교환 경로, TXT는 문자열 정보, SRV는 서비스의 위치·우선순위 등을 제공합니다. MX가 있다는 사실로 그 도메인의 모든 발신 메일을 신뢰할 수 없습니다. PTR도 소유자·사용자·악성 여부를 보증하지 않습니다.

CNAME은 DNS에서 이름을 연결하고 HTTP 302는 웹 응답이 다른 URL로 이동하라고 알리는 동작입니다. 공통 사례에서는 N05가 HTTP 이동을, N06이 DNS 별칭과 주소 응답을 나타냅니다. 이 둘을 한 종류의 리다이렉트로 합치지 않습니다.

## 응답·캐시·관측 위치

N03은 WS-024가 리졸버에 보낸 조회 기록입니다. N04는 리졸버의 외부 질의로 출발지가 10.20.10.53입니다. N04만 보면 원래 단말이 누구였는지 알 수 없습니다. N09는 캐시 응답이어서 외부 경계에서 대응 질의가 없을 수 있습니다.

TTL은 캐시 보관에 관련된 값이며 악성 여부의 척도가 아닙니다. 작은 TTL은 정상 부하 분산에서도 사용됩니다. NXDOMAIN은 이름 부재 응답으로, 연결 성공이나 감염을 의미하지 않습니다. 응답 코드, 반환값, 시각과 출처를 함께 기록합니다.

## 현재 환경에 추가할 지식

AAAA와 IPv6 경로를 놓치면 IPv4만 조사한 결과가 전체로 보일 수 있습니다. RFC 9460의 SVCB/HTTPS 레코드는 서비스 접속 정보를 제공합니다. 암호화 DNS와 ECH 관련 설정도 DNS가 연결하는 정보이므로 A 레코드만 보는 습관을 넓혀야 합니다. 모든 조직이 이 기능을 사용한다고 전제하지는 않습니다.
