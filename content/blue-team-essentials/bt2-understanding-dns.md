## DNS가 하는 일

DNS는 이름에 연결된 여러 정보를 조회하는 분산 시스템입니다. 웹 주소의 IP뿐 아니라 메일 서버, 서비스 위치와 텍스트 정보도 제공합니다. 모든 이름이 하나의 주소로, 모든 주소가 하나의 이름으로 대응하는 것은 아닙니다.

## 클라이언트와 서버 역할

| 역할 | 설명 | 보이는 주소의 의미 |
| --- | --- | --- |
| Stub Resolver | 호스트가 조회를 시작하는 기능 | 클라이언트 요청 후보 |
| Forwarder | 다른 리졸버로 질의를 전달 | 원래 클라이언트가 가려질 수 있음 |
| Recursive Resolver | 필요한 서버를 따라 답을 얻고 캐시 | 여러 사용자의 요청이 모임 |
| Authoritative Server | 담당 zone의 데이터를 제공 | 해당 zone의 응답 출처 |

한 실제 서버가 여러 역할을 수행할 수 있습니다. OS의 캐시·앱·브라우저·보안 제품 설정도 다릅니다. 모든 Linux 또는 Windows가 동일한 캐시 동작을 한다고 가정하지 않습니다.

## 캐시가 없는 조회 예

시험 이름 portal.study.example을 조회한다고 가정합니다. 클라이언트는 리졸버에 묻고 리졸버는 루트·관련 상위 zone·담당 권한 서버의 위임 관계를 따라 답을 얻을 수 있습니다. 캐시가 있으면 이 단계가 모두 반복되지는 않습니다.

리졸버가 인터넷 DNS 서버로 UDP·TCP/53 통신하는 것은 정상 해석 과정일 수 있습니다. 다만 승인된 리졸버·실제 질의·관측 위치를 확인합니다. 주소만으로 정책 위반을 결정하지 않습니다.

## 주요 레코드

| 타입 | 역할 | 예와 주의 |
| --- | --- | --- |
| A / AAAA | IPv4 / IPv6 주소 | 여러 주소·기간별 변경 가능 |
| PTR | 주소의 역방향 이름 | 정방향 이름·소유자 보증 아님 |
| CNAME | 다른 이름을 가리키는 별칭 | HTTP 리다이렉트와 다름 |
| MX | 메일 교환 서버와 우선순위 | 발신자가 아니라 수신 경로 탐색 |
| TXT | 문자열 정보 | SPF·검증 정보 등 정상 용도 존재 |
| SRV | 서비스·프로토콜·호스트·포트 | 우선순위·가중치도 포함 |
| NS | 담당 이름 서버 정보 | 서버 주소는 별도 해석 가능 |
| SOA | zone의 관리·일련번호·타이머 등 | zone 관리 맥락 확인 |

SRV 이름 _ldap._tcp.study.example은 서비스·프로토콜을 지정합니다. 응답에서 호스트·포트와 우선순위·가중치를 읽습니다. 언더스코어가 있다고 악성 이름이 되는 것은 아닙니다.

## 응답과 TTL 읽기

NOERROR는 처리 상태이고 원하는 레코드가 반드시 존재한다는 보장은 아닙니다. NXDOMAIN은 이름 부재, SERVFAIL은 처리 실패이며 원인과 답 섹션을 확인합니다. TTL은 캐시 조건이지 도메인 안전 기간이나 연결 시간은 아닙니다.

오늘 새로 조회한 답과 사건 당시 답이 다를 수 있습니다. 당시 질의·응답·기간이 있는 자료를 우선 연결합니다.

**작은 활동:** 위 레코드에서 웹 주소, 메일 목적지, AD 서비스 위치와 텍스트 인증에 필요한 타입을 고릅니다.

**완료 기준:** 질의자·리졸버·권한 서버, 이름·주소·캐시·응답을 구분합니다.

## 최신 보강과 실무 연결

SVCB·HTTPS 레코드와 DoH·DoT·DoQ는 추가로 확인합니다. DNSSEC는 데이터 출처·무결성 검증이며 질의 암호화가 아닙니다. [DNS 조사](dns-investigation.html)에서 실제 로그와 연결합니다.
