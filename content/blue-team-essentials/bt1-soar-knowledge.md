## 자동화할 작업과 판단을 나누기

경보에서 계정·세션을 추출하고 승인된 API로 자산·계정 정보를 조회하는 것은 반복 작업입니다. 조회 결과를 합쳐 담당과 다음 질문을 제안할 수도 있습니다. 그러나 맥락이 부족한 값 하나로 운영 계정을 차단하는 것은 더 큰 권한과 검증이 필요한 결정입니다.

오케스트레이션은 이 작업들을 연결합니다. 어떤 작업이 앞선 결과를 필요로 하는지, 어떤 조건에서 분기하는지, 실패했을 때 누구에게 넘기는지를 정합니다. 자동화의 가치는 사람의 클릭 수 감소뿐 아니라 누락·대기·재현성을 개선하는 데 있습니다.

## 작업 상태를 최소한 세 가지로 구분하기

조회 결과에는 성공·대상 없음·실패를 구분합니다. 성공이지만 정보가 불완전할 수도 있습니다. 외부 평판 결과가 없다는 것과 외부 서비스에 접속하지 못했다는 것은 다릅니다. 둘 다 정상 판정으로 처리하면 위협을 숨길 수 있습니다.

| 상태 | 처리 | 남길 기록 |
| --- | --- | --- |
| 성공, 정보 있음 | 맥락을 추가해 분석 | 출처·시각·응답·신뢰도 |
| 성공, 대상 없음 | 알려진 정보 없음으로 표시 | 조회 대상과 자료 범위 |
| 실패·시간 초과 | 제한된 재시도 후 담당 인계 | 오류·시도·다음 담당 |

필수 정보가 없으면 변경 조치를 멈추고 수동 확인으로 넘길 수 있습니다. 비상 조치 기준이 사전에 승인돼 있다면 그 범위에 따라 진행하되, 누락된 정보와 실행 이유를 기록합니다.

## 요청과 효과를 구분하는 설계

공통 사례 D13은 세션 폐기 요청이고 D14는 서비스 감사 성공입니다. 작업을 보냈다는 HTTP 성공만으로 실제 세션의 후속 활동이 멈췄다고 단정하지 않습니다. 대상 식별, 요청 ID, 서비스 실행 결과, 필요한 후속 상태 확인을 연결합니다.

메일 규칙 제거, 다른 세션·토큰, 실제 전달 범위는 별도 작업입니다. 동일 계정의 한 세션을 폐기했다고 모든 지속 접근이 사라진 것은 아닐 수 있습니다. 조치별 범위와 검증 질문을 플레이북에 넣어야 합니다.

## 중복 방지와 재시도

재전송된 경보가 같은 조치를 두 번 실행하지 않도록 사건·경보·대상·조치 유형·버전을 조합한 작업 키를 사용할 수 있습니다. 동일 키의 이미 완료된 작업인지 확인하고, 실패했던 작업을 어떤 조건에서 재시도할지 정합니다. 이것이 중복 방지 설계이며 키 자체는 환경에 맞춰 정합니다.

시간 초과가 발생했다고 작업이 실제로 실행되지 않은 것은 아닐 수 있습니다. 재시도 전에 서비스 측 상태나 요청 ID를 조회할 수 있는지 확인합니다. 무제한 재시도는 API 제한과 업무 영향을 키웁니다. 최대 시도·간격·중단 조건·담당을 설정합니다.

## 권한과 기록

조회 역할과 변경 역할을 구분하고 필요한 최소 권한을 사용합니다. 승인 단계에는 승인자·대상·시각·범위를 남깁니다. 인증 정보는 안전한 비밀 관리 기능에서 가져오고 실행 로그에 출력하지 않습니다. 실행 결과에는 민감한 응답 전체 대신 재검토에 필요한 근거와 허용된 저장 위치를 연결할 수 있습니다.

학습에서는 실제 변경 API를 연결할 필요가 없습니다. 워크북에 성공·실패·중복 입력의 예상 상태를 작성하고 D13·D14·D15의 관계를 검토하는 것으로 시작합니다. 운영 반영에는 환경별 검증과 승인된 조치 범위가 필요합니다.

## 지식과 코드를 함께 유지하기

지식 문서에는 정상 맥락·분류 이유·조사 방법을 적습니다. 코드 저장소에는 탐지·스크립트·설정·테스트 자료를 버전으로 관리합니다. 문서에서 실행 버전을 연결하고 코드 변경에는 이유와 검증을 남깁니다. 이전 버전으로 되돌릴 때 자료 구조도 호환되는지 확인합니다.

AI 도구가 요약을 작성하는 경우에도 원문 ID·검색 조건·미확인 판단을 보존합니다. 그럴듯한 요약을 새 증거로 취급하지 않습니다. 서비스의 데이터 처리 조건과 허용된 입력 범위는 조직 정책에 맞게 정합니다. 분석가가 검토해야 할 책임과 변경 권한은 그대로 명시합니다.

## 학습 활동

“조회 실패”, “조치 요청 시간 초과”, “동일 경보 재전송”의 세 상황에 대해 멈출 조건·재시도·다음 담당을 작성하세요. 정상 결과와 실패를 구분하고 조치가 중복 실행되지 않는지 설명할 수 있어야 합니다.
