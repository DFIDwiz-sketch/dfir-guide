## 방어 가능한 환경은 관측과 통제가 이어진다

교재의 Defensible Network Concepts는 네트워크 보안 제품을 많이 설치하는 장이 아닙니다. 자산과 소유자를 알고, 활동을 관측하며, 노출과 접근을 통제하고, 그 상태가 유지되는지 평가하는 관점입니다. “모든 단말에 에이전트가 있다”라는 설명만으로 클라우드 제어면, 미관리 장치, 외부 SaaS의 활동까지 볼 수 있는 것은 아닙니다.

## 여덟 가지 특성을 작업으로 바꾸기

| 특성 | 의미 | 확인할 자료·작업 |
| --- | --- | --- |
| Monitored | 관련 활동을 볼 수 있음 | 센서·감사 로그와 수집 상태 |
| Inventoried | 자산과 중요한 속성을 알고 있음 | 호스트·계정·SaaS·서비스 목록 |
| Controlled | 접근과 행위를 제한할 수 있음 | 경계·계정·권한·변경 정책 |
| Claimed | 책임질 소유자가 있음 | 업무·운영·데이터 소유자 |
| Minimized | 불필요한 노출을 줄임 | 서비스·권한·외부 연결 검토 |
| Assessed | 위험과 통제 상태를 평가 | 취약점·구성·노출 검토 |
| Current | 목록·설정·자료를 현재 상태로 유지 | 변경 반영과 재검토 기록 |
| Measured | 위 특성이 실제 충족되는지 측정 | 관측 범위·공백·통제 검증 지표 |

등록된 자산이지만 소유자가 없으면 조치를 승인할 사람이 없습니다. 소유자가 있어도 수집이 끊기면 행동을 볼 수 없습니다. 관측할 수 있어도 접근 통제가 없다면 발견 후 피해를 줄이기 어렵습니다. 특성들은 서로 보완합니다.

## 네트워크·호스트·서비스는 다른 질문에 답한다

교재의 NSM(Network Security Monitoring)은 네트워크 활동 관측을, CSM(Continuous Security Monitoring)은 지속적인 보안 상태·활동 관측의 관점을 설명합니다. 이 사이트의 온디맨드 호스트 실습을 지속 수집 체계가 구현된 것처럼 표현하지 않습니다.

네트워크 관측은 통신 상대·프로토콜·연결 순서·전송 특징을 보여줍니다. 호스트 관측은 실행 프로세스·사용자·파일·서비스·설정 변경에 더 가깝습니다. 클라우드와 SaaS 감사는 로그인, 권한, 앱 승인, 관리 설정, 서비스 내부 활동을 보여줍니다. 어느 하나가 다른 자료를 완전히 대신하지 않습니다.

공통 사례 D09는 내부 PC의 DNS 조회, D10은 그 PC의 승인된 백업 프로세스입니다. D05·D07은 외부 미관리 장치에서 사용된 SaaS 세션과 메일 설정입니다. 내부 PC에 이상이 없더라도 SaaS 계정 사건이 없다는 뜻은 아닙니다. 조사 대상이 같은 계정인지, 같은 장치인지, 같은 세션인지 따로 확인해야 합니다.

## 중앙화의 의미와 한계

여러 출처를 공통 검색 위치로 모으면 자료를 옮겨 다니는 시간이 줄고 계정·자산·시각을 기준으로 연결할 수 있습니다. 그러나 중앙화는 품질 문제를 자동으로 해결하지 않습니다. 시간 해석, 필드 매핑, 중복, 누락, 파서 오류와 보관 기간을 관리해야 합니다.

PCAP는 패킷 원문이고 Zeek 같은 프로토콜 로그는 패킷에서 만든 구조화된 기록입니다. 원시 EVTX 파일도 검색 전에 파싱·정규화가 필요할 수 있습니다. SIEM에 프로토콜 로그를 넣었다고 해서 모든 패킷 본문이 그 안에 저장된 것은 아닙니다. 필요한 상세 원문을 어디에서 얼마나 오래 찾을 수 있는지도 관측 지도에 적습니다.

## “지금 수집”과 “계속 관측”을 구분하기

온디맨드 호스트 수집은 조사 시점에 확보 가능한 상태와 남아 있는 자료를 가져오는 방식입니다. 이는 지속적인 호스트 이벤트 수집과 다릅니다. 사전에 기록하지 않았거나 보존 기간이 지난 활동을 나중의 수집으로 모두 재구성할 수는 없습니다. 도구가 실행됐다는 사실보다 어떤 자료를 어느 기간에 확보했는지가 중요합니다.

교육용 사례 D16은 미관리 장치의 호스트 자료가 없다는 상태 기록입니다. 이를 악성 프로세스 부재로 해석하지 않습니다. 대신 서비스 감사와 사용자 확인으로 판단할 수 있는 범위를 적고, 필요한 다른 세션·메시지 추적을 요청합니다.

## 학습 활동

자산·계정·SaaS·네트워크 센서를 행으로, 관측 질문·자료·기간·담당·공백을 열로 하는 표를 작성합니다. 중요한 행동 하나마다 어떤 자료로 확인할지 표시하고 확인할 자료가 없다면 “미관측”이라고 적으세요. 두 분할 학습에서 관측 질문과 수집 품질을 자세히 연습합니다.

## 최신 보강과 공개 참고자료

클라우드에서는 서비스 유형과 권한에 따라 얻을 수 있는 감사 자료가 달라집니다. 제어면·계정·서비스 감사, 수집 지연과 무결성까지 포함하여 관측 범위를 검토합니다.
