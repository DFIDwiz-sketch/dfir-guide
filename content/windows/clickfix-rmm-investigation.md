## 무엇을 구분할 것인가

ClickFix는 오류 수정이나 인증을 가장해 사용자가 명령을 직접 실행하도록 유도하는 사회공학 기법입니다. 인포스틸러는 브라우저 저장 자료·세션·기타 비밀정보 탈취를 목표로 할 수 있습니다. RMM은 정상 원격관리 소프트웨어이지만 승인되지 않은 접근에 악용될 수 있습니다. 셋은 같은 악성코드 이름이 아니며 하나의 사건에 연결되기도 합니다.

Microsoft의 [2025년 ClickFix 분석](https://www.microsoft.com/en-us/security/blog/2025/08/21/think-before-you-clickfix-analyzing-the-clickfix-social-engineering-technique/)과 [2026년 9월 RMM 분석](https://www.microsoft.com/en-us/security/blog/2026/09/29/phishing-abuses-rmm-tools-persistent-access/)을 배경으로 한 조사 가이드입니다. 실제 의심 명령을 따라 실행하는 과정은 필요하지 않습니다.

## 1단계 — 유입과 사용자 행동 보존하기

신고 메시지·첨부파일·URL·브라우저 방문 시각·화면과 사용자가 수행한 행동을 확보합니다. 사용자를 탓하기보다 ‘어디서 무엇을 보았고 어떤 동작을 했는지’ 확인합니다. URL을 조사용 PC에서 바로 열거나 클립보드 내용을 셸에 붙이지 않습니다.

가짜 오류 페이지를 보았다는 사실, 명령을 복사한 사실, 프로세스가 실행된 사실은 별개입니다. 각각 근거가 있는지 표시합니다. 브라우저 기록이나 Windows RunMRU도 단독으로 실행 완료를 증명하지 않습니다.

## 2단계 — 실행의 연결점 찾기

4688 또는 Sysmon 1 등 실제 수집된 프로세스 자료에서 사용자·로그온 세션·프로세스 시작 시각·부모·명령행·경로를 확인합니다. PowerShell·cmd·스크립트 실행기 이름은 후보 단서입니다. 정상 관리와 설치에서도 등장합니다.

| 연결할 자료 | 확인하는 내용 | 해석의 한계 |
| --- | --- | --- |
| 브라우저·메일 | 유입 시각과 사용자 접점 | 자동 열람·리디렉션 가능 |
| 프로세스 생성 | 무엇을 누가 실행했는지 | 명령행 감사가 없으면 세부 누락 |
| 파일·해시·서명 | 내려받거나 설치된 대상 | 서명 유효가 정상 의도를 보장하지 않음 |
| DNS·연결·프록시 | 목적지와 전송 맥락 | TLS 본문·프로세스가 없을 수 있음 |
| 서비스·예약 작업 | 지속 실행 설정 | 설정 존재와 실제 실행은 다름 |

사용자가 실행 창을 사용하면 브라우저가 직접 부모 프로세스로 나타나지 않을 수 있습니다. ‘브라우저 → PowerShell’ 관계만 요구하는 탐지의 누락을 고려합니다.

## 3단계 — RMM의 승인과 세션 조사하기

자산의 승인된 원격관리 도구 목록, 운영 주체·테넌트, 설치 변경 기록, 실제 연결 세션과 접속자를 비교합니다. 동일 제품도 정상 회사 인스턴스와 승인되지 않은 인스턴스가 함께 존재할 수 있습니다. 제품명만으로 허용 목록을 만들지 않습니다.

프로그램 설치 시간, 자동 시작·서비스, 설정 파일, 관리 콘솔의 세션 기록, 원격 작업과 파일 전송을 가능한 범위에서 수집합니다. 에이전트 하나를 제거한 뒤 다른 원격 접근 경로가 남아 있는지도 조사합니다.

## 4단계 — 비밀정보 노출 범위 정하기

파일 실행이 확인되면 당시 브라우저·업무 앱·SSH 키·개발 토큰·암호 관리자 접근 상태를 자산 역할에 따라 검토합니다. 존재한 모든 비밀정보가 유출됐다고 단정하지 않되 ‘확인된 접근’, ‘노출 가능’, ‘자료 부족’을 나눕니다.

정상 계정의 새 장치·세션·메일 규칙·앱 동의는 [클라우드 조사](cloud-identity-response.html)로 연결합니다. 단말을 깨끗이 만들었다는 이유로 탈취된 토큰이나 다른 기기에서의 접근이 끝났다고 보지 않습니다.

## 5단계 — 차단·복구를 검증하기

진행 중인 원격 세션과 의심 단말을 필요한 범위에서 격리하고 증거를 보존합니다. 승인되지 않은 관리 등록을 해제하고 노출 범위의 자격 증명·세션을 통제합니다. 비밀번호 변경은 감염 의심 단말이 아닌 신뢰할 수 있는 장비에서 수행합니다.

예방은 사용자 안내, 최소 권한, 애플리케이션 통제, 브라우저·메일 보호와 RMM 관리 정책을 조합합니다. 정상 관리 도구를 전부 차단하기보다 운영 경로와 허용 범위를 정하고 시험합니다.

## 6단계 — 무해한 관찰로 탐지 점검하기

시험 Windows에서 직접 PowerShell을 열고 `Get-Date` 한 번만 실행합니다. 이것은 공격 재현이나 ClickFix 방어 성능 평가가 아니라 **사용자가 실행한 셸이 수집 경로에서 보이는지** 확인하는 관찰입니다. 원본 로그 → 수집 → SIEM을 비교하고 부모·계정·명령행 중 무엇이 남는지 기록합니다.

**완료 기준:** 유입·실행·지속 접근·비밀정보 노출을 분리한 타임라인과 미확인 항목을 작성합니다. 단순 명령 관찰만으로 ‘인포스틸러 탐지 성공’이라고 기록하지 않습니다.
