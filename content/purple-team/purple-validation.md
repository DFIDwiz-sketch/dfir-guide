## 공동의 검증 기준 만들기

퍼플팀은 공격과 방어를 연결해 보안 가정을 확인하는 협업 방식입니다. 재현 여부와 경보 발생만 확인하지 않고 조사와 대응에 필요한 증거가 남았는지도 봅니다.

## 네 단계의 루프

| 단계 | 확인할 내용 |
| --- | --- |
| 재현 설계 | 목적, 대상, 행동과 예상 데이터 |
| 실행·관찰 | 정확한 시각, 계정·장비와 실제 결과 |
| 탐지·조사 | 원문 수집, 필드, 경보와 조사 연결 |
| 수정·재검증 | 정책·수집·규칙 수정 후 같은 조건 비교 |

이 루프는 실무에서 활용하기 위한 정리입니다. 데이터 수집을 먼저 시험하면 도구 동작과 탐지 실패를 구분하기 쉽습니다.

## NTLM 검증 예시

SMB signing을 요구하는 대상에서 보호가 실제 적용되는지 확인합니다. 정상 인증과 정상 업무의 성공 여부, 보호 없는 접근 거부, 관련 감사 자료를 각각 기록합니다. SMB만 시험했으면 LDAP·HTTP·AD CS에 같은 보호 효과가 있다고 가정하지 않습니다.

## 결과를 남기는 형식

- 행동과 ATT&CK 기술
- 대상 서비스·계정·설정과 시험 시각
- 원래 예상한 데이터 및 실제 확보한 데이터
- 경보 발생 여부와 조사자가 설명할 수 있었던 범위
- 발견한 빈틈, 수정 사항, 재검증 결과

**차단 성공**, **탐지 성공**, **조사 가능**, **정상 업무 유지**를 별도 항목으로 평가합니다. 개선 전후의 조건이 다르면 결과를 직접 비교하지 않습니다.
