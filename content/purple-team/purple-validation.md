## 목표와 준비물

하나의 정상 실습 행동이 **호스트 원문 → 수집 서버 → SIEM → 경보 → 조사**까지 연결되는지 확인합니다. 퍼플팀은 공격과 방어의 지식을 함께 사용해 이 연결을 개선하는 협업 방식입니다.

시험 Windows 한 대, 시험 계정, 확인할 수집 경로와 [예약 작업 실습](scheduled-tasks.html)을 준비합니다. 실제 공격 재현 전에도 이 정상 행동으로 데이터와 운영 절차의 기초를 검증할 수 있습니다.

## 1단계 — 한 행동과 성공 기준 합의하기

이번 실험은 `DFIR-Lab-Observe`라는 무해한 작업을 생성·실행·변경·삭제하고 기록을 추적하는 것입니다. 담당자, 대상 장비, 시간, 수집할 채널과 정리할 항목을 적습니다.

| 성공 기준 | 확인 방법 |
| --- | --- |
| 행동 완료 | 실제 작업 상태와 출력 결과 |
| 수집 완료 | 원본 이벤트와 수집 결과의 동일 기록 확인 |
| 검색·탐지 | 예상 후보·경보와 근거 원문 확인 |
| 조사 가능 | 주체·대상·행동·한계를 설명 |
| 정상 업무 유지 | 시험 외 기능과 사용자 업무 영향 확인 |

이 실험은 수집·탐지 경로를 검증합니다. 별도의 공격을 차단하는 시험을 하지 않았다면 ‘공격 차단 성공’으로 표시하지 않습니다.

## 2단계 — 예상 데이터 표 작성하기

생성은 4698, 변경은 4702, 삭제는 4699를 예상하되 감사 조건을 확인합니다. 실제 실행은 4688 또는 Sysmon 1과 작업 실행 결과로 보완합니다. 로컬에서 현재 시각만 쓰는 작업은 별도의 외부 통신이 필요하지 않습니다.

**남길 결과:** 이벤트 종류마다 어느 장비·채널에 있어야 하는지, 누가 확인할지, 수집·검색에서 사용할 식별자는 무엇인지 적습니다.

## 3단계 — 재현 시각과 실제 결과 기록하기

[예약 작업 가이드](scheduled-tasks.html)에 따라 한 단계씩 실행합니다. 생성과 실행, 수정과 삭제를 서로 다른 시각으로 기록하고 각 단계가 실제 성공했는지 확인합니다. 실패한 동작을 탐지 시스템의 실패로 계산하지 않습니다.

실행한 작업 이름, 계정과 대상 장비를 정확히 적고 시험 중 추가로 만든 파일·설정도 정리 목록에 넣습니다. 결과를 보기 좋게 만들려고 실패 기록을 삭제하지 않습니다.

## 4단계 — 수집 경로를 한 구간씩 검증하기

| 구간 | 찾을 근거 | 없을 때 다음 확인 |
| --- | --- | --- |
| 호스트 원본 | Event ID·Record ID·시각 | 감사·채널·실제 행동 |
| Velociraptor | Client·Flow·Artifact·결과 | 대상·접속·필터·권한·오류 |
| 전송·색인 | 전달 내역과 원문 | 전송 파이프라인·대상 인덱스 |
| Splunk 검색 | 정확한 필드와 기간 | 시간 파싱·필드·검색 권한 |
| 경보 | 규칙·실행 이력·근거 | 스케줄·조건·억제·중복 처리 |

호스트 자료를 필요할 때만 가져오는 환경에서는 Hunt 실행 시점이 따로 있습니다. 지속 관찰이 목표라면 Client Monitoring 또는 적합한 상시 수집 경로가 실제로 구성돼 있어야 합니다.

## 5단계 — 지연을 측정하고 원인 분류하기

호스트 발생 시각, 서버 수신 시각, SIEM 색인 시각과 경보 생성 시각을 별도로 기록합니다. 서로 다른 시스템의 시계 오차를 먼저 확인합니다. 수집 시각과 이벤트 시각이 같으리라 가정하지 않습니다.

실패는 행동 미완료, 원본 미기록, 수집 누락, 전송·파싱 실패, 검색 조건, 경보 운영과 조사 절차로 나눕니다. ‘탐지 안 됨’ 한 줄보다 수정할 위치가 명확해집니다.

## 6단계 — 한 가지를 바꾸고 재검증하기

감사·수집 필터·필드 매핑·규칙 중 확인된 문제를 고칩니다. 바뀐 설정과 버전을 남기고 같은 조건의 작업을 새로운 기록 식별자로 다시 수행합니다. 여러 항목을 한꺼번에 바꾸면 어떤 변화가 효과를 냈는지 구분하기 어렵습니다.

정상 사례도 다시 검색해 불필요한 경보가 늘지 않았는지 확인합니다. [탐지 설계](blue-detection.html)의 후보 조건은 악성 판정이 아니므로 일치 기록의 해석을 별도로 기록합니다.

## 7단계 — 결과와 후속 과제 정리하기

```text
실험 ID / 날짜 / 담당:
대상·계정·행동과 승인 범위:
예상 원문과 실제 기록 ID:
구간별 수신·색인·경보 시각:
실패 지점과 확인된 원인:
수정 내용과 재시험 결과:
미검증 조건과 다음 시험:
시험 자료·작업 정리 결과:
```

**완료 기준:** 다른 분석가가 같은 조건으로 재현하고 개선 전후를 비교할 수 있습니다. SMB 보호만 확인한 결과를 LDAP·HTTP·AD CS까지 확대하지 않는 것처럼, 모든 결론에 실제 시험한 범위를 표시합니다.
