## 적용할 상황

이례적인 이름 해석 응답, NTLM 인증 출발지 불일치, LSASS 접근 뒤의 인증이나 인증 직후 서비스·AD·인증서 변경이 관찰됐을 때 조사합니다. 단일 징후만으로 공격을 확정하지 않습니다.

## 1. 인증의 경로 복원

원래 클라이언트, 중간 장비와 실제 대상 서비스를 식별합니다. 시간대와 주소·포트·계정·인증 결과를 연결하고 NAT·프록시와 정상 관리 장비를 고려합니다.

## 2. 증거 교차 확인

| 자료 | 확인 목적 |
| --- | --- |
| Security 4624 / 4625 | 대상의 로그온 결과와 인증 패키지 |
| Security 4776 | 자격 증명 검증 장비와 결과 |
| NTLM Operational | 감사 설정에 따른 추가 인증 맥락 |
| 프로세스·LSASS 접근 | 인증 유도·비밀정보 노출의 맥락 |
| 네트워크·서비스 로그 | 실제 접속 경로와 후속 요청 |

로그 해석과 감사 조건은 [NTLM 전체 가이드](ntlm.html)의 ‘감사 설정과 수집할 증거’를 함께 참고합니다.

## 3. 공격 방식과 영향 분리

- 인증 자료 캡처만 있었는가?
- 진행 중인 인증이 다른 서비스로 Relay됐는가?
- NT hash가 유출돼 새 인증에 사용됐는가?
- 실제 파일 접근, 실행, 권한 변경이나 인증서 발급이 있었는가?

인증 성공과 후속 행동 성공도 구분합니다. 대상의 signing·CBT·EPA 요구와 인증된 계정의 실제 권한을 확인합니다.

## 4. 억제와 복구

관련 장비·인증 경로를 제한하고 증거를 보존합니다. 노출된 비밀값의 범위를 확인해 계정·서비스 비밀값을 회전하며 활성 세션, 지속성과 AD 변경을 정리합니다. 인증서 악용은 비밀번호 변경만으로 끝나지 않아 발급 내역과 인증 경로를 별도 처리합니다.

## 5. 재검증

유도 경로·서비스 보호·자격 증명 보호의 빈틈을 수정합니다. 정상 업무와 차단 효과를 확인하고 탐지에 필요한 자료가 계속 수집되는지 검증합니다.
