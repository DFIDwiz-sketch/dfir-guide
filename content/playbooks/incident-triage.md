## 적용 범위

의심 프로세스, 비정상 로그인이나 네트워크 경보를 처음 확인했을 때 쓰는 기본 흐름입니다. 사건의 확산 위험과 업무 영향을 평가하며 조사와 격리를 병행합니다.

## 1. 상황 확인

- 경보 원문과 탐지 조건을 확보합니다.
- 장비·계정·서비스·시각과 시간대를 식별합니다.
- 정상 관리 작업과 비교하고 영향을 받는 업무를 확인합니다.
- 이미 확산 중인지, 추가 장비가 관련됐는지 판단합니다.

## 2. 증거 보존과 억제

확산을 막기 위한 격리·연결 제한을 수행하면서 필요한 로그·패킷·휘발성 자료를 보존합니다. 재부팅·삭제·계정 변경은 증거와 서비스에 영향을 주므로 조치 시점·대상·결과를 기록합니다.

## 3. 범위 확인

| 확인 대상 | 조사할 내용 |
| --- | --- |
| 초기 접근 | 파일 유입, 요청과 사용자 행동 |
| 실행·지속성 | 프로세스, 서비스와 예약 작업 |
| 계정·인증 | 자격 증명 노출과 다른 대상 접근 |
| 네트워크 | 외부 연결, 내부 이동과 데이터 전송 |
| 변경·영향 | 파일, 계정·권한과 인증서 |

확인된 관찰과 가설을 분리해 [타임라인](evidence-timeline.html)에 기록합니다. 하나의 해시나 IP만으로 관련 사건을 전부 묶지 않습니다.

## 4. 제거와 복구

원인·지속성과 침해 계정을 처리하고 필요한 비밀값을 회전합니다. 정상 업무의 복구와 재발 조건의 제거를 각각 검증합니다. 자격 증명·AD·인증서 침해가 포함되면 해당 범위의 복구 절차로 확대합니다.

## 5. 마무리 기록

영향받은 장비·계정·기간, 확보한 증거, 수행한 조치, 남은 불확실성과 개선 과제를 정리합니다. 탐지·수집의 빈틈은 재검증 가능한 과제로 만듭니다.

이 순서는 실무 적용을 위한 요약입니다. NIST SP 800-61 Rev. 3의 위험 관리 및 대응 지침을 함께 참고하세요.
