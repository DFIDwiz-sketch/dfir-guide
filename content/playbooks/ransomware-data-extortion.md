## 목표와 준비물

랜섬웨어 대응은 파일 복호화만의 문제가 아닙니다. 계정 침해, 자료 탈취, 백업·관리 체계 손상과 서비스 중단을 별도로 조사합니다. 암호화가 없더라도 자료 탈취·협박 사건은 발생할 수 있습니다. 아래는 기술적 조사·복구 절차이며 신고·계약 의무 판단은 조직 담당자가 관할과 현행 요구사항에 맞춰 진행합니다.

준비물은 비상 연락망, 자산·계정·백업 목록, 격리 권한, 중앙 로그와 별도의 신뢰할 수 있는 소통 경로입니다. [CISA StopRansomware](https://www.cisa.gov/stopransomware/ransomware-guide), [ASD ACSC 대응·복구](https://www.cyber.gov.au/report-and-recover/recover-from/ransomware)를 기본 자료로 사용합니다.

## 1단계 — 피해 진행 여부와 우선 차단 결정하기

파일 변경·접근 불가, 여러 장비의 경보, 공유 저장소 이상, 백업 작업 변경, 대량 외부 통신을 확인합니다. 각 신호는 원인 후보이지 곧바로 랜섬웨어 확정은 아닙니다. 담당자에게 서비스 영향과 현재 진행 중인 행동을 전달합니다.

진행 중인 암호화·확산은 신속히 차단합니다. 네트워크 격리와 계정·원격 접근 제한을 검토하고 대규모 종료·재부팅은 가용성 및 증거 영향을 고려해 결정합니다. 무조건 전원을 끄거나, 증거를 완벽하게 모을 때까지 차단을 지연하는 식의 단일 규칙을 적용하지 않습니다.

## 2단계 — 증거와 시간을 보존하기

랜섬노트, 변경 파일의 표본·해시, 원본 로그, 로그인·원격 접속, 프로세스, 백업·하이퍼바이저 관리 이력과 조치 기록을 확보합니다. 상황이 허용하면 휘발성 자료도 수집합니다. 암호화된 파일과 원본이 모두 있다면 각각 보존하고 원본 증거에 복구 도구를 시험하지 않습니다.

발견 시각, 최초로 확인한 의심 행동, 자료가 남아 있는 가장 이른 시각을 구분합니다. ‘처음 발견된 장비’를 반드시 최초 진입 장비로 취급하지 않습니다.

## 3단계 — 영향 범위 세 갈래로 나누기

| 범위 | 주요 자료 | 결론에 필요한 근거 |
| --- | --- | --- |
| 암호화·파괴 | 파일 변경, 프로세스·저장소·EDR | 실제 영향 파일과 실행 맥락 |
| 자료 유출 | 파일 접근·압축, 프록시·흐름, 클라우드 감사 | 어떤 자료가 어디로 전송됐는지 |
| 통제권·복구 손상 | 관리자·백업·가상화·IdP 감사 | 공격자가 바꾼 권한·설정과 복구 경로 |

아카이브 파일 생성은 유출 완료가 아닙니다. 큰 outbound 바이트도 어떤 자료인지 설명하지 못합니다. 공격자의 유출 주장·공개 표본은 별도 검증하고, 네트워크 볼륨·파일 접근·목적지·서비스 감사를 함께 봅니다. 유출 증거가 없더라도 로그 부재와 유출 부재를 구분합니다.

## 4단계 — 진입점·지속 접근·자격 증명 제거하기

외부 서비스, VPN, 피싱, 원격관리 도구, 특권 계정 사용을 관련 증거에 따라 조사합니다. 감염 파일 하나만 삭제하지 말고 지속 접근, 탈취된 계정·토큰, 변경된 정책과 신뢰 관계를 확인합니다. 도메인·테넌트 관리 권한이 영향을 받았다면 개별 PC 복구보다 범위가 커집니다.

백업 관리 계정은 업무 사용자와 분리해 검토합니다. 사건 중 기존 신뢰 체계로 새 비밀번호를 배포하면 다시 노출될 수 있어 안전한 관리자 장비·소통·인증 경로를 확보합니다.

## 5단계 — 격리된 복원 시험하기

복구 지점의 시각뿐 아니라 침해 이전 여부, 무결성, 복원 가능성을 확인합니다. 오프라인·불변 백업도 설정과 실제 삭제·보존 권한을 시험해야 합니다. 깨끗한 복구 환경에 필요한 서비스부터 복원하고 검증 없이 감염망에 다시 연결하지 않습니다.

| 확인 항목 | 검증 방법 |
| --- | --- |
| 데이터 사용 가능성 | 대표 문서·DB·업무 트랜잭션 읽기·쓰기 시험 |
| 신뢰 회복 | 패치·계정·세션·권한·관리 경로 재검토 |
| 지속 접근 제거 | 관련 자동 실행·에이전트·계정 재발 확인 |
| 관측 복구 | 호스트·네트워크·백업 이벤트 도착 확인 |
| 복구 목표 | 허용 데이터 손실(RPO)·복구 시간(RTO)과 실제 결과 비교 |

백업 성공 표시만으로 복구 능력이 검증되지는 않습니다. 실제 복원 시험에서 실패한 종속 서비스·인증서·키도 기록합니다.

## 6단계 — 정상화와 후속 헌팅 수행하기

단계적으로 연결을 복구하고 계정 사용·외부 세션·동일 지속성·백업 변경을 재확인합니다. 재발 감시 기간은 침해 범위와 보존 데이터에 따라 정합니다. 특정 며칠 동안 경보가 없다는 이유만으로 모든 잔존 위험이 사라졌다고 결론 내리지 않습니다.

**완료 기준:** 영향 자산·유출 판단·제거 근거·복원 결과·미확인 범위가 분리된 보고서를 작성합니다. 작은 시험 데이터의 복원과 타임라인을 연습하는 것으로 시작하고 실제 암호화 도구를 실행할 필요는 없습니다.
