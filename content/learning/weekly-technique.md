## 주간 노트의 구성

| 항목 | 기록할 것 |
| --- | --- |
| 원리 | 어떤 구조와 조건에서 가능한 행동인가 |
| 실습 | 대상·계정·설정·시각과 실제 결과 |
| 호스트 흔적 | 로그 채널·이벤트·아티팩트와 실제 필드 |
| 네트워크 흔적 | 연결·프로토콜·패킷과 센서의 한계 |
| 탐지 | 조건·정상 사례·실행 결과와 근거 이벤트 |
| 대응 | 격리·원인 수정·복구·재검증 |
| 남은 질문 | 누락 데이터와 확인하지 못한 조건 |

## 시작할 여덟 주제

이 목록은 학습 예시입니다. NTLM·Kerberos 같은 프로토콜 자체는 ATT&CK 기술 하나와 같은 분류가 아니므로 실제 행동을 고른 뒤 기술을 매핑합니다.

| 순서 | 주제 | 확인할 결과물 |
| --- | --- | --- |
| 1 | PowerShell 실행 — T1059.001 | 실행 원리·프로세스·로그의 연결 |
| 2 | 예약 작업 — T1053.005 | 작업 XML·변경·실제 실행 |
| 3 | Windows 서비스 | 실행 계정·프로그램·시작과 로그 |
| 4 | NTLM 인증과 재사용 | Relay와 PtH의 조건·보호 차이 |
| 5 | Kerberos | 티켓 발급과 서비스 접근의 구분 |
| 6 | 자격 증명 접근 | 접근 흔적과 정상 보안 도구의 구분 |
| 7 | SMB·RDP·WMI·WinRM | 인증·프로세스·서비스·통신의 연결 |
| 8 | 웹셸·외부 통신 | 요청과 서버 실행·후속 연결의 구분 |

## 첫 주의 정상 실행 관찰

실습 Windows에서 정상 PowerShell 명령을 실행해 프로세스 생성 로그가 기록되는지 먼저 확인합니다. 감사·Sysmon·PowerShell 로깅의 현재 설정과 버전을 기록합니다. 의도한 행동이 관찰되지 않으면 수집부터 수정한 뒤 탐지 조건을 만듭니다.

## 완료 기준

다른 사람이 노트만 보고 대상 조건과 관찰 결과를 재확인할 수 있어야 합니다. 경보가 발생했는지와 실제 원문·후속 행위를 설명할 수 있었는지를 분리합니다. 결과가 없는 영역에는 미수집·미관찰·행동 부재 중 무엇인지 남깁니다.
