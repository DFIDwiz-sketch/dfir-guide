## 목표와 준비물

한 주에 한 행동을 골라 **원리 → 관찰 → 탐지 → 대응 → 재검증**을 기록합니다. 매주 도구를 바꾸는 대신 동일한 조사 습관을 쌓는 것이 목표입니다. 시험 VM, 수집 경로와 메모 양식이 필요합니다. 시작 전 [첫 조사 실습](first-investigation.html)으로 자료를 연결하는 방법을 익힙니다.

## 1단계 — 월요일: 관찰할 행동 정하기

이번 주 행동을 한 문장으로 정합니다. 첫 주는 “시험 사용자로 PowerShell에서 현재 시각을 출력하고 프로세스 생성과 스크립트 기록을 비교한다”로 시작합니다. MITRE T1059.001은 공격자의 PowerShell 사용을 분류하는 기술이며 정상 PowerShell 실행 자체를 침해로 판정하는 기준은 아닙니다.

기록할 항목은 대상 VM, 사용자, OS·PowerShell 버전, 감사 설정, 관찰할 채널과 실습 시간입니다. 사용할 수 없는 자료도 먼저 적습니다.

## 2단계 — 화요일: 정상 실행 하나 관찰하기

시험 Windows에서 다음처럼 무해한 명령을 새 PowerShell 프로세스로 실행합니다.

```powershell
powershell.exe -NoProfile -Command "Get-Date -Format o"
```

실행 전후 시각을 기록합니다. 프로세스 생성 감사가 켜져 있다면 4688을, Sysmon이 해당 이벤트를 수집한다면 이벤트 1을 확인합니다. PowerShell 4104는 관련 스크립트 블록 로깅과 버전·설정에 따라 관찰 가능하므로 이 명령이 모든 환경에서 4104를 반드시 만든다고 가정하지 않습니다.

**확인할 결과:** 본인이 실행한 프로세스를 시각·계정·부모·명령행으로 찾을 수 있어야 합니다. 로그가 없으면 공격 탐지를 만들기 전에 수집 경로를 검증합니다.

## 3단계 — 수요일: 호스트와 네트워크를 비교하기

호스트 원문과 Velociraptor 수집 결과를 비교하고, SIEM에 전달한다면 같은 기록을 찾아봅니다. 위의 현재 시각 출력 명령은 업무상 네트워크 요청을 만들 필요가 없으므로 해당 명령과 연결되는 네트워크 흔적이 없어도 자연스럽습니다. 같은 시간의 다른 통신을 억지로 연결하지 않습니다.

**남길 결과:** 관찰된 이벤트 ID·Record ID·Flow ID와 각 수집 지점의 도착 시각입니다.

## 4단계 — 목요일: 검색과 정상 사례 비교하기

프로세스 이름만 검색하는 시작 조건을 만든 뒤 경로·계정·명령행·부모 정보를 추가합니다. 작성한 검색으로 방금 만든 정상 실행이 어떻게 보이는지 확인합니다. 정상 실행이 경보로 잡혔다면 어떤 맥락을 더 봐야 하는지 적습니다.

같은 명령을 한 번 더 실행해 중복 집계와 시간 범위도 확인합니다. 실습 한 번 성공했다고 다양한 공격 변형을 모두 탐지한다고 결론 내리지 않습니다.

## 5단계 — 금요일: 대응 메모와 재검증 작성하기

다음 내용을 한 페이지로 정리합니다.

| 항목 | 남길 내용 |
| --- | --- |
| 원리 | 해당 프로그램·권한·실행 구조 |
| 재현 | 대상, 계정, 명령과 실제 시각 |
| 관찰 | 호스트·네트워크 증거 및 미관찰 이유 |
| 탐지 | 검색 조건, 정상 사례와 누락 조건 |
| 대응 | 확인이 필요한 자료와 판단별 조치 |
| 재검증 | 수집·검색 수정 전후 결과 |

원문이나 민감한 자료를 공개 게시하지 않고, 공개 글은 가상값·허가된 자료로 구성합니다. 자기 환경의 시험 기록은 적절한 보관 위치에서 관리합니다.
