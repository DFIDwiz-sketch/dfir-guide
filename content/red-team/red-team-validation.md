## 목표와 준비물

공격자의 관점에서 보안 가정을 검증하고 방어 측에서 확인할 증거를 설계합니다. 목표는 도구 실행 횟수보다 실제 조건·영향·개선점을 설명하는 것입니다. 조직이 정한 평가 범위 또는 별도 시험 랩, 역할·연락 방법과 변경 복원 계획을 준비합니다.

이 입문 절차에서는 [정상 예약 작업](scheduled-tasks.html)과 같은 제한된 행동을 사용합니다. 정상 행동 관찰은 수집 준비를 검증할 수 있지만 그 자체로 전체 공격 캠페인에 대한 방어 능력을 증명하지는 않습니다.

## 1단계 — 검증할 보안 가정 고르기

‘우리 환경이 안전하다’는 표현 대신 확인 가능한 문장을 만듭니다. 예를 들어 “지정된 시험 호스트의 예약 작업 생성·변경을 수집하고 담당자가 주체와 실행 대상을 설명할 수 있다”입니다.

**결과물:** 가정, 성공·실패 기준, 해당 기준을 측정할 자료를 각각 적습니다. 기술적 실행 성공과 방어의 관찰 성공은 별도 항목입니다.

## 2단계 — 범위와 중단 조건 문서화하기

| 항목 | 구체적으로 적을 내용 |
| --- | --- |
| 대상 | 시험 장비·서비스·계정과 제외 대상 |
| 시간·연락 | 실시 시간, 담당자와 중단 연락 방법 |
| 허용 행동 | 실제 실행할 동작과 허용된 변경 |
| 데이터 | 사용할 시험 자료와 수집·보관 범위 |
| 중단 기준 | 예기치 않은 서비스 영향·범위 초과의 처리 |
| 복원 | 만든 파일·작업·계정과 원상 확인 방법 |

문서의 경계를 실제 도구의 대상 선택과 비교합니다. 실습용 라벨이나 목록이 잘못돼 여러 장비에 실행되지 않도록 실행 전 대상 수와 식별자를 확인합니다.

## 3단계 — 행동을 ATT&CK과 연결하기

전술은 목적, 기술은 행동의 방법을 설명합니다. 도구 이름 하나를 기술 하나로 고정하지 않습니다. 예약 작업으로 실행을 예약하는 행동은 T1053.005에 연결해 학습할 수 있으나 사용된 목적과 맥락을 함께 남깁니다.

인증, 자격 증명 접근, 재사용, 원격 실행과 지속성은 서로 다른 관찰 항목입니다. [NTLM](ntlm.html)과 [Kerberos](kerberos-basics.html)에서 가능한 조건과 필요한 비밀값·티켓의 차이를 먼저 이해합니다.

## 4단계 — 작은 정상 행동으로 관찰 기반 확인하기

단일 호스트에서 무해한 동작을 수행하고 정확한 시각·계정·명령·결과를 남깁니다. 예상 로그가 없으면 방어 측과 정책·센서·전송을 확인합니다. 실행 자체가 실패한 경우에는 로그가 없다는 결과를 차단·미탐으로 단순 분류하지 않습니다.

관찰 기반이 확인된 뒤 조직이 승인한 평가 시나리오의 행동과 단계로 확장합니다. 이 문서는 외부 서비스에 대한 공격 대상이나 실행 범위를 제공하지 않습니다.

## 5단계 — 실제 조건과 증거 수집하기

| 평가 관점 | 기록할 근거 |
| --- | --- |
| 실행 가능성 | 실제 계정 권한·설정·서비스 조건 |
| 실행 결과 | 성공·실패와 출력·상태 변화 |
| 관찰 가능성 | 원문·센서·수집 서버·SIEM 기록 |
| 대응 가능성 | 조사자가 알 수 있는 주체·대상·영향 |
| 정상 운영 | 업무 영향과 복원 확인 |

한 통제의 실패가 모든 경로의 실패라는 결론은 아닙니다. 예를 들어 하나의 서비스에서 인증 보호 조건을 확인했어도 다른 서비스에는 별도의 검증이 필요합니다.

## 6단계 — 방어팀과 차이를 설명하기

공격 측의 실제 행동 기록과 방어 측의 관찰 타임라인을 비교합니다. 경보가 없었던 원인이 센서 가시성, 수집, 파싱, 규칙, 운영 절차 중 어디에 있는지 확인합니다. 경보는 났지만 조사자가 주체를 특정할 수 없었다면 조사 가능성의 빈틈으로 기록합니다.

조용히 지나갔다는 결과만 적기보다 어떤 데이터가 있으면 결론을 바꿀 수 있는지 제시합니다. 구체적인 수정·재시험 방법은 [퍼플팀 검증](purple-validation.html)에 연결합니다.

## 7단계 — 복원과 보고서 완성하기

직접 만든 시험 자료·작업·계정·변경을 목록대로 정리하고 정상 운영을 확인합니다. 발견 사항은 조건, 관찰 근거, 영향, 개선책과 재검증 방법으로 씁니다. 실제로 시험하지 않은 조건은 미검증으로 남깁니다.

**완료 기준:** 해당 환경과 권한에서 무엇이 가능했고, 방어 측이 무엇을 확인했으며, 어떤 수정으로 어떤 위험을 줄일지 설명하는 보고서를 완성합니다.
