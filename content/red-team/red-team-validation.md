## 무엇을 검증하는가

레드팀 활동은 공격자의 관점에서 예방·탐지·대응이 실제로 작동하는지 확인하는 보안 검증입니다. 단순한 취약점 개수와 달리 계정, 프로토콜, 서비스와 운영 흐름을 연결해 영향을 평가합니다.

## 시작 전에 정의할 것

| 항목 | 기록할 내용 |
| --- | --- |
| 목표 | 검증할 보안 가정과 성공 기준 |
| 범위 | 대상, 계정, 시간과 허용된 활동 |
| 중단 조건 | 서비스 영향·범위 초과 시 절차 |
| 증거 | 실행 시각, 대상과 관찰 결과 |
| 정리 | 테스트 자료·계정·변경 사항의 제거 |

이 문서의 구조는 평가 설계용 제안입니다. 실제 활동의 조건은 해당 조직과 실습 환경의 승인 범위에 맞춥니다.

## 행동을 ATT&CK으로 설명하기

전술은 공격자가 달성하려는 목적, 기술은 그 목적에 쓰는 방법을 설명합니다. 하나의 도구가 여러 기술에 쓰일 수 있어 도구 이름만으로 행동을 분류하지 않습니다.

예를 들어 자격 증명 수집, 그 자료의 재사용, 원격 실행과 지속성 설정은 서로 다른 행동입니다. [NTLM 가이드](ntlm.html)에서 Relay와 Pass-the-Hash의 조건 차이를 확인할 수 있습니다.

## 결과물

실행한 행동, 실제 성공·실패 조건, 방어에서 관찰한 증거와 남은 영향을 구분합니다. 탐지되지 않은 이유가 수집 누락인지, 필드·분석 문제인지, 대응 절차 문제인지 확인하면 개선 과제가 구체적이 됩니다.

[퍼플팀 검증 루프](purple-validation.html)는 공격 재현과 방어 측 확인을 연결하는 방법입니다.
