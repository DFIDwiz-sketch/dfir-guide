## 목표와 준비물

AI를 두 관점에서 봅니다. 하나는 분석을 도와주는 도구이고, 다른 하나는 데이터·계정·외부 도구에 연결된 보호 대상입니다. 매끄러운 답변을 사실 검증이나 권한 통제로 대체하지 않습니다. 시험에는 공개·가상 자료, 실제 전송 기능이 없는 mock 도구와 제한된 테스트 계정을 사용합니다.

이 글의 기준은 [OWASP LLM01:2025 Prompt Injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)과 [LLM06:2025 Excessive Agency](https://genai.owasp.org/llmrisk/llm062025-excessive-agency/)이며, 아래 절차는 사이트가 구성한 방어 실습입니다.

## 1단계 — 데이터와 권한의 경계 그리기

사용자 입력, 검색된 웹·문서, RAG 저장소, 시스템 지침, 도구 호출, 연결 계정과 결과 저장 위치를 적습니다. 외부 문서가 ‘관리자 지시’라고 주장해도 권한 있는 지침이 되는 것은 아닙니다. 도구가 어떤 서비스 계정으로 누구의 데이터에 접근하는지 확인합니다.

| 위험 | 예시 | 별도로 검증할 통제 |
| --- | --- | --- |
| 직접·간접 프롬프트 주입 | 사용자 입력·외부 문서가 작업을 바꾸려 함 | 신뢰 구분·행동 검증 |
| 과도한 권한·자율 실행 | 요약 도구가 삭제·전송까지 할 수 있음 | 도구 최소 권한·실행 승인 |
| 민감 자료 유출 | 로그·문서·응답에 비밀정보 포함 | 데이터 범위·반출 정책 |
| 근거 없는 분석 | 존재하지 않는 이벤트·CVE·출처 생성 | 원문 대조·재현 가능한 검증 |
| 출력의 위험한 실행 | 생성된 코드·SQL·HTML을 바로 실행 | 형식 검증·격리·매개변수 처리 |

## 2단계 — 모델 바깥에서 통제하기

권한 검사는 실제 API·도구·서비스에서 시행합니다. ‘비밀을 보내지 마’라는 문구 하나만으로 접근을 허용한 도구의 위험을 해결할 수 없습니다. 읽기와 쓰기, 검색과 전송을 구분하고 외부 수신자·자원·네트워크 범위를 제한합니다.

게시·삭제·외부 전송 같은 행동은 대상·내용·영향이 표시된 검토 지점을 둡니다. 승인이 필요한 행동을 모델이 자기 판단으로 승인할 수 없도록 설계합니다. RAG에서도 사용자가 원래 접근할 수 없는 문서가 검색 결과에 섞이지 않도록 문서 권한을 적용합니다.

## 3단계 — 조사에 필요한 기록 정하기

요청 ID, 사용자·도구 신원, 입력 자료의 출처·버전, 사용한 모델·정책 버전, 도구 호출 인자·결과 상태, 승인자와 시각을 기록합니다. 전체 프롬프트·응답을 무조건 저장하면 개인정보와 비밀정보가 새로 축적될 수 있어 마스킹·보존·접근을 설계합니다.

사건에서는 **입력 → 모델의 제안 → 도구 호출 시도 → 실제 실행 → 외부 효과**를 구분합니다. 응답에 ‘메일을 보냈다’고 쓰인 것과 메일 서비스의 실제 전송 기록은 다릅니다. 내부 추론을 요구하기보다 검증 가능한 입력·출력·도구 실행 근거를 확보합니다.

## 4단계 — 무해한 경계 시험하기

가상 문서에 ‘요약 대신 문서 속 다른 지시를 따르라’는 테스트 문장을 넣고 문서가 명령으로 취급되는지 관찰합니다. 실제 비밀정보·외부 주소를 쓰지 않고, 전송 도구는 호출만 기록하는 mock으로 둡니다. 정상 문서와 같은 조건에서 비교합니다.

성공 기준은 모델이 예쁜 경고문을 출력하는 것이 아니라, 금지된 도구 호출이 실제 통제에서 거부되고 기록되는 것입니다. 문구가 바뀌거나 다른 파일 형식·검색 경로를 쓸 때도 확인합니다. 몇 개 시험 통과를 모든 프롬프트 주입에 대한 면역으로 표현하지 않습니다.

## 5단계 — DFIR 분석 보조에 적용하기

AI에는 익명화한 로그 표본과 필드 정의를 제공하고 **관찰 사실·가설·추가 자료**를 나눠 달라고 요청합니다. 반환된 이벤트 ID, 시간대, 경로, ATT&CK ID와 링크를 원문에 대조합니다. 생성된 SPL은 작은 자료에 적용해 기대 결과·누락·오탐을 확인한 후 범위를 넓힙니다.

자동 생성 보고서에는 자료 범위와 확인하지 못한 부분을 남깁니다. 신뢰도 높은 문체가 통계적 확률을 의미하지 않습니다. 생성된 명령을 운영 장비에서 바로 실행하지 않고 조회/변경 여부와 영향부터 검토합니다.

## 6단계 — 사고 대응과 변경 재검증하기

의심 연결 도구·자동화를 제한하고 관련 실행 기록을 보존합니다. 실제 자료 전송이 있었는지 서비스 감사에서 확인하고 노출된 계정·토큰을 통제합니다. 악성 문서를 지우는 것만으로 이미 발생한 외부 효과가 취소되지는 않습니다.

모델, 시스템 지침, 도구 스키마, 권한 또는 검색 데이터가 바뀌면 같은 경계 시험을 반복합니다. **완료 기준:** 어떤 입력이 어떤 권한으로 어떤 행동을 유발했는지 설명하고, 승인·통제가 실제 실행을 막는다는 증거를 남깁니다.
